# Codex 评审纪律

约束本仓改动的评审方式。写这类改动时这份规则常驻上下文，不需要主动去读。

## 工作流

**Claude 写，Codex 审。** 仓内文件的改动由 Claude 直接落盘，Codex 只做只读评审。这条覆盖了
`CLAUDE.md` 默认的「写入经 cc-suite implement 落盘」——用户已明确改成本条。评审用只读的
`review-plan`（架构/简化类）；真机与正确性核查用 `audit`。

audit → fix → verify 轮（含 push 前仓规一轮）的 fix 段同样受七维约束：audit 给出的
修复清单不照单全收，每项落地前先按下述七维评估，会退化的项调整方案或明确遗留并记录
理由（用户裁定 2026-09-02）。先例：pool 进 runtime manifest 会破坏包的设备无关身份
（通用性/爆炸半径）；attempts 有序前缀校验把遍历实现细节升成契约（泛化性）。

## 触发条件

出现以下任一情形，就做一次 checkpoint：提交一个逻辑完整的单元，并跑一次 Codex 评审。

- 手写源文件累计改动 >300 行，或 ≥4 个手写源文件。手写源指 `SKILL.md`、`references/*.md`、
  `scripts/*.py`、`assets/template/*`。
- 改到**核心裁决/校验逻辑**（`package.py` 的 check、`accept.py` 的 verdict）或**对外契约**
  （README 模板、`facts-schema`、`perf-protocol`、状态码、精度阈值）——不论几行，无条件触发。

以下不计入、不单独评审：

- 生成产物（`assets/example/**`、`*_test.csv`、渲染出的 README 与 verify 脚本）——它们由
  重渲染逐字节保证，不看行数。
- 纯机械改动（行长回流、示例重渲、常量表搬运）。

## 七个评审维度

每条评审结论都要从这七维出发打分并给理由：

1. **通用性**——对当前范围内的算子/场景是否普遍适用，不是只对手头这个。
2. **泛化性**——加新算子或新 CANN 版本时是否无需再加特判；变化是否被隔离在数据或 FACTS。
3. **简单性**——是否用了最少的机制、最少的特判、最短的代码达到同样正确性。
4. **清晰性**——写法与结构是否清楚（「写得清不清楚」）。
5. **复杂度**——最高优先级；能塌成一条通用规则或一个默认的，就不该是 N 个特判。
6. **冷读可理解性**——一个第一次来、技术上没问题的**人**，只读文档能不能顺畅读懂。判据除
   **措辞、组织、表达**外，还包括**术语可解性**：每个本仓自造的术语、缩写、前缀、字段名与状态值，
   在首次使用处必须有就地定义或指向定义的链接。专查三类——**用了没定义 / 定义在别处却无指向 /
   先用后释**。标准是**人读懂写作本身**，**不许假定读者靠背景补齐**——agent 会把人读不懂的地方
   脑补过去，所以「agent 跟着能做」不等于过。这是本 skill 的命根（验收零上下文）。
7. **爆炸半径**——达到同样目标，这处改动扰动了多少**既有**代码与契约。判据是改动的**足迹**，
   不是设计本身的机制多少（那是复杂度）：机制极简也可能半径巨大（改一个被广泛依赖的字段名），
   机制不简也可能半径很小（隔离的新模块），所以它是独立一维。专查五点——**追加还是改写**（在旁边
   加，还是拆掉重写既有流程）、**触及几个承重文件/对外契约**、**是否跨 skill/模块波及**、**是否逼
   既有可用流程连带改动或重新验证**、**能否中途止损与回滚**。同样正确性下，**半径更小的更优：
   追加优于改写，隔离优于横切，可止损优于不可逆。**

## 原则

避免过于复杂。复杂不等于健壮——它降低可维护性，甚至降低健壮性；健壮来自更少更强的不变量与
一个 fail-closed 默认，不是更多特判。

让评审显式处理维度之间的冲突（如简单 vs 覆盖完整），给出权衡结论，而不是单维最优。

冷读可理解性要用**全新 session**（不 resume、零上下文）去读才测得准，因为 resume 的评审带着
上一轮的上下文，不是冷读者。

审可读性时**不要给评审「假定读者技术上没问题、别挑背景」这类限定**——它会把「术语没定义」
一并排除掉。踩过:一次编辑评审只评措辞、明说假定读者懂背景，结果 `TC_PF_` 用了没定义没被审到。
术语可解性和写作质量是两条正交的轴，一次评审要么两条都查，要么分两次查，别用一条把另一条挡掉。
