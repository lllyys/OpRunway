# 中文写作规则

移植自上游 `repo-task-atk-test`（基线 13b3f88）。上游仓根即本仓 `plugin/`：文中 `skill/`、
`docs/` 对应本仓 `plugin/skill/`、`plugin/docs/`。

适用于 skill 文档与 `docs/guide/`。完整词表与替代写法在 `.claude/hooks/doc_style_lint.py`，
命中时 lint 输出替代写法。规则出处见 `docs/development/skill-authoring-basis.md`。

不检查的内容：代码块、行内代码、链接目标、引用块（`>`）、「」内的引述原话、
文件名为 `golden-*`、`*-template`、`*-example` 的样例。

## 规则

「机检」列：是 = 命中退 1；报数 = 只打印计数；否 = 靠评测与复审。

| 编号 | 规则 | 反例 → 正例 | 机检 |
| --- | --- | --- | --- |
| ZH-P1 | 中文与英文、中文与数字之间加空格 | 「进S1前」→ 进 S1 前 | 是 |
| ZH-P2 | 中文语境用全角标点 | 「新机(CANN 9.0)」→ 新机（CANN 9.0） | 是，`--fix` 可修 |
| ZH-P3 | 英文或数字与全角标点之间不加空格 | 「退出码 0 。」→ 退出码 0。 | 是 |
| ZH-S1 | 单句不超过 60 字；超过就拆句或改成列表 | — | 报数 |
| ZH-S2 | 写要做什么，不写不要做什么。只有红线用否定句，并给出替代做法 | 「不要手工搬这些文件」→ 由 `freeze_golden.py` 移动这些文件 | 报数 |
| ZH-S3 | 主语明确，用主动语态；主语按下方「主语」表选 | 「文件会被脚本删除」→ 脚本删除该文件 | 否 |
| ZH-S4 | 标题用名词短语；不用疑问句，不用「它」；章节名先从下方「章节名」表挑 | 「报告怎么读」→ 报告字段 | 是 |
| ZH-S5 | 代词指代明确，不跨段回指；「那份」「这类」指代不清时写出名称 | 「那份不到 1 KB」→ `facts.json` 不到 1 KB | 否 |
| ZH-W1 | 不用本仓自造词或低频书面词；确需简称的登记进下方术语表 | 「判据」→ 完成条件；「剖面」→ `backend` 取值；「量具」→ 检查脚本 | 是 |
| ZH-W2 | 一个概念只用一个术语，术语表里的禁用同义词不出现 | 「基线」→ 标杆 | 是 |
| ZH-W3 | 不用口语 | 「重跑碰不对」→ 重新运行无效；「跑」→ 运行 | 是 |
| ZH-W4 | 不用冷僻、生造、文言词 | 「唯二」→ 仅有的两种 | 否 |
| ZH-W5 | 不用填充词、模糊词、第一人称、拟人、将来时 | 「必要时」→ 写出条件；「我们的」→ 本包的 | 是 |
| ZH-T1 | 加粗只用于红线，每节不超过 3 处 | — | 报数 |
| ZH-T2 | 运行时文档不写开发史。出处写成「（实测）」或源码路径；演进过程写进 skill 的 `CLAUDE.md` 或 `docs/development/` | 「曾按 backend 统一处理，起因是……」→ 删去，只留当前做法 | 是 |

## 主语

| 文档 | 读者 | 主语 |
| --- | --- | --- |
| `SKILL.md` | 执行的 agent | 祈使句 |
| `references/` | 查阅中的 agent | 描述机制与条件，不出现人称 |
| `docs/guide/` | 使用 skill 的人 | 祈使句；区分动作方时用「助手」 |

写成约定，不写成对话脚本：「你说什么 / 它问什么 / 你拿到什么」这类写法改成输入、处理、输出。
