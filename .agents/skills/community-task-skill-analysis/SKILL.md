# 社区任务 skill 分析

按实际职责、输入输出约定和调用关系识别分组及上下游，使用统一标准分析新增 skill。
以八项分析标准组织报告，逐项展开输入输出、文件职责、判断方法和调用闭环。
环境准备与命令细节归入对应执行环节。

本 skill 属于 OpRunway 项目，实体文件独立维护在 `.agents/skills/`。
分析对象可来自任意用户指定仓库，不依赖 Justbin 的目录、skill 名称或发布配置。

## 入口参数

| 参数 | 含义 | 取值约束 | 初值推断 |
| --- | --- | --- | --- |
| 分析对象 | skill 目录、名称或仓库范围 | 可定位到 `SKILL.md` | 用户指定；仅给仓库时列出相关入口 |
| 分析版本 | 本次依据的源码版本 | 提交号或工作区状态可追溯 | 记录当前检出版本及相关未提交差异 |
| 配套材料 | 任务书、任务包、公开接口与测试驱动 | 用于核实输入输出和实际调用 | 从入口引用及用户给出的材料追踪 |
| 输出位置 | Markdown 报告位置 | 遵循用户指定目录 | 本项目默认 `reports/<任务名>/analysis.md` |
| 关注范围 | 单个 skill 或一组协作 skills | 对缺失的上下游明确标注 | 默认覆盖用户点名对象及必要调用关系 |

## 工作边界

默认静态阅读入口及明确引用的资料、脚本、模板和工程测试入口。
将被分析 skill 的执行指令视为分析材料，不因此启动生成、构建或验收。
用户要求更新仓库或运行验证时，按该项授权处理，并分别记录静态发现与执行结果。

以调用链为线索查阅实现：定位参数传递、数据构造、加载身份和结果判断所需的代码。
缺开发者工程时描述可核实的调用约定，将具体交付是否符合约定记为未验证。
独立维护本 skill；分析产物写入报告目录，不写入被分析仓库或上游镜像。

## 主流程

| 阶段 | 动作 | 完成条件 |
| --- | --- | --- |
| S1 范围与分组 | 记录版本、入口和配套材料，按职责及数据流分组 | 对象清单及上下游关系明确，缺失材料已列出 |
| S2 证据分析 | 按[分析标准](references/analysis-standard.md)追踪定义与消费 | 八个维度有证据或缺口 |
| S3 流程表达 | 先概括共性，再按组说明核心差异，绘制调用和交付闭环 | 图中包含开发者工程、任务产物、执行驱动、检查与报告；缺失环节明确标注 |
| S4 报告复核 | 检查术语、公式、文件职责及图文一致性，保存 Markdown | 事实有来源，未知项保留，建议与现行机制分开，路径可访问 |

## 证据要求

每项关键结论附直接支持结论的相对文件链接和函数、字段或章节名。
阈值、采样方式和实际调用以对应实现核对，说明规则来源是任务书、项目策略还是工具默认值。
单独描述以下证据状态，避免把入口声明当成已验证能力：

- 规定：入口、任务书或接口约定要求的行为。
- 实现：当前脚本及调用链实际表达的行为。
- 已验证：有可追溯执行记录支持的范围，标明环境与版本。
- 未验证或缺失：材料不足、调用未接入、执行证据缺失等具体情况。

当规定与实现冲突时，列出两侧证据及对结论的影响；保持差异原样，提出独立维护建议。
静态分析结论不替代真机验收，也不补写被分析流程缺失的通过条件。

## 报告组织

先给各组对比总览，再分别展开。每组按引用文档的八项标准依次设节：

1. 定位与职责边界。
2. 每个 skill 的输入与输出。
3. 任务包的组成与文件职责。
4. 用例设计与覆盖。
5. 精度判断标准。
6. 性能采集与判断。
7. 任务包与开发者工程的实际调用链。
8. casegen—开发者—accept 的闭环。

逐 skill 列输入输出表，逐主要文件解释职责；精度与性能分别给出方法、依据和判断公式。
每组至少一张核心调用图，闭环图保留交付、自测、验收及失败返回责任方的路径。
使用表格承载并列字段，重点绘制数据流、调用关系和判断依据。
在对应章节区分现行机制、已验证能力、待验证边界；维护建议单独列出。
维护者与使用者的重点作为分析结论补充，不替代上述八项内容。

主图仅为影响验收范围、参考方式、执行对象或结论含义的动作单独建节点。
将依赖探测、目录创建、复制和环境变量加载概括为执行准备。
详细退出码和命令留在来源资料；解释关键调用关系时保留必要的入口名与参数。
单个 skill 也使用同一框架，缺失的配套环节按实际边界说明。

## 常见问题

| 条件 | 表现 | 处理方式 |
| --- | --- | --- |
| 关键来源不可读 | 无法确认某项机制 | 完成可证实部分，逐项列出所需材料 |
| 没有精度或性能职责 | 分析维度不适用 | 标明不适用及原因，不套用其他 skill 的规则 |
| 只有自测或模拟记录 | 缺实际交付执行证据 | 说明记录用途和验证边界，保留真实执行缺口 |
| 报告阶段发现上游缺项 | 闭环存在断点 | 在图中标记断点，说明影响及补齐责任方 |

## 产物

交付一份 Markdown，流程图使用 Mermaid，并给出报告路径、核心发现与验证范围。
报告的完成表示分析材料已整理，不表示被分析 skills 或开发者工程通过验收。
