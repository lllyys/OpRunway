# cc-suite project context

- Language: Python 3, standard library first.
- Source: `plugin/oprunway/`; public entry: `plugin/oprunway_cli.py accept`.
- Tests: `python3 -m unittest discover -s plugin/tests -v`, executed in the NPU target environment for formal review.
- External runtime: preinstalled ATK 26.5.14 and CANN; installation is environment preparation, not plugin behavior.

Review invariants:

1. Keep one ATK-backed path. Do not restore `acc-common`, a parallel generator/golden/runner, public stage subcommands,
   or a second verdict producer.
2. Production logic is capability/ABI driven and contains no witness-operator branches or private machine values.
3. `oprunway.verdict.finalize` is the only verdict producer. Incomplete evidence never becomes PASS.
4. Only a complete numerical mismatch may directly become `DUT_FAIL`; build, ATK, adapter, environment, timeout and
   missing-evidence failures remain non-DUT statuses.
5. Preserve caller-trusted association, taskdoc/operator-source/full-build-input anchors, fresh build/package, vendor ELF and symbols, actual loaded
   library, ATK cases and required-case denominator, normal-case CPU/DUT outputs, expected-error workbook results,
   optional raw profiler CSV, and receipt hashes.
6. Dirty session directories are read-only. Every formal run uses a nonexistent ASCII path and a maximum 7200-second
   active budget.
7. The workflow does not run, collect or consume GPU data. Unmeasured GPU/resource/relative-performance clauses remain
   structured `unvalidated_requirements` and must not be described as passed.
8. Do not read or use bureau/canon unless the user explicitly requests a bureau/canon records task.
