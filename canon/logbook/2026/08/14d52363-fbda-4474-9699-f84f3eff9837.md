## [2026-08-05T21:20:00Z] session 14d52363 — 本地 checkout 成为一等被测来源 + runner_form 准入收敛

**Intent.** 按 `doc/oprunway-session-handoff-2026-08-05.md` 实施：让「任务书给本地路径 + 被测代码给本地目录」与「在线 PR 链接」成为平级的两条来源通路，并把 `runner_form` 的验收准入收敛到 `cpp_extension`。用户口径：不问来源，默认传入的就是正确的。

**Decisions.**

- 本地事实**不塞进 `payload.pr`**：新开平级键 `local_checkout` + 判别式 `dut_source`，两个来源键互斥出现、混装即拒。一个叫 `pr` 的字段里装本地 checkout 数据，下游、报告、人读收据时都会把弱 provenance 误当成 PR provenance — implies dossier DUT source discrimination
- 判别式缺省 `pull_request` 且 PR 通路**不写这个键**：老收据不会一夜失效，PR 通路业务字段一个没动。但取值写错（拼错、伪造）与缺席是两回事，必须当场拒 — implies dossier DUT source discrimination
- 本地通路的 provenance 锚是被测子树 Merkle 摘要 `root_digest`，替代 PR 的 `head_sha`。收据里的 `local_checkout.git.head_sha` 是**信息字段不是锚**（worktree 可能 dirty），读锚一律走 `dut_source.identity()`，不许按字段名翻 `head_sha` — implies dossier DUT source discrimination
- **`aclnn_py` + `local_checkout` 是结构性 fail-closed，不是待办**：`aclnn_adapter` 只能按 PR ref 在容器内重新取源 build，构建端不存在可与 `local_root_digest` 对账的锚。接入状态表因此需要第三种状态（⛔），不能与「⬜ 待接」混为一谈 — implies dossier DUT source discrimination
- 正式验收准入收敛到 `cpp_extension`（唯一跑通完整 torch_parity 矩阵的通路）。门落两处：`_resolve_mode` 入口 + 写 `acceptance.json` 之前的出口门。只拦入口拦不住——照抄 `repo_adapter` 对 catlass_mock 后门的处置口径。`--allow-experimental-form` 放行执行、不放行产验收裁决 — implies dossier Runner form admission
- **能力表不是准入表**：`repo_adapter.SUPPORTED_NP_BY_FORM` / `DEFERRED_NP_BY_FORM` 的 `aclnn_py`/`cpp` 条目保留不动。前者回答「支持哪些 dtype」，后者回答「能不能出裁决」 — implies dossier Runner form admission
- `changed_files` 算不出来时记字符串 `"unavailable"`，**绝不是 `[]`**——后者语义是「确实没有改动」，两件事必须分得开 — implies dossier DUT source discrimination
