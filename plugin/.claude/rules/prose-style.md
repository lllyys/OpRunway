# skill 文档行文规则

约束本仓所有自己写的 markdown：`SKILL.md`、`references/*.md`、各级 `CLAUDE.md`、
`README.md`、`docs/skills/**`。
写这些文件时这份规则常驻上下文，不需要主动去读。

## 病灶

本仓早期有一条规则「每行至多一个句号」，本意是短句易读，实际把 Markdown 的三个
排版层级压成了一个。2026-08-18 实测验收 skill：823 个正文自然段里 726 个只有一句话，
连续三个以上单句段的地方有 87 处，最长一串 17 个（`plugin-authoring.md:27-59`）。

结果是段落这一层不存在，读者无法判断哪几句属于同一个论点。更糟的是单句独占行
本该用于强调判据和禁令，当它变成默认排版，强调就失效了——**强调所有等于强调没有**。

单句风格还会诱发注水：一个意思拆成三句写，每句独占一行，读着有节奏但信息量没增加。
合并成段后重复的部分一眼可见。

## 三个层级

写之前先判断这段内容属于哪一层：

| 层级 | 用在什么地方 | 形态 |
| --- | --- | --- |
| **段落** | 几句连贯的论证、因果、铺垫 | 正常成段，句子之间不空行 |
| **列表** | 并列的观点、条件、步骤 | 无先后用 `-`，有先后或步骤用 `1. 2. 3.` |
| **单句独占段** | 需要醒目的判据、禁令、结论 | 前后空行，一段一句 |

三层都要用到。全用段落读起来没有抓手，全用单句段就是现在这个病。

## 规则

1. 并列观点 ≥2 条就结构化成列表，不要堆成连续句子
2. 列表前补一句领起句，说明这是在列什么
3. 连贯的论证正常成段，不要每句一段
4. 单句独占段留给判据、禁令、结论，不做默认排版
5. 一个观点只写一次，不要为了强调而复述
6. 一行不超过 100 字符
7. 一个自然段不超过 5 句

## 机械判据只抓子集

`tests/test_document_style.py` 实现了四条可判定的：

- 行长 ≤100（规则 6）
- 连续 ≥3 个单句自然段 → 红（规则 3、4）
- 同一段内连续 ≥3 行各自以句号结句 → 红（规则 1）
- 单个自然段 >5 句 → 红（规则 7）

**脚本没红不等于合规。** 它抓不到只有两条的并列，抓不到软换行写成的并列，
也判断不了「这几句到底是并列还是递进」。规则 1 到 5 的判断责任在写字的人，
脚本只兜住最明显的那一类。

判据为什么用「行末是不是句号」区分：朴素做法「连续三行短句就该加项目符号」
误报率约一半，因为软换行的一句话也是连续三行。两者唯一可机械区分的地方在行末，
软换行的行末是逗号、顿号、破折号或半个词，独立并列句每行自己收句号。

## 存量走棘轮

验收 skill 有 102 处存量违规，不阻塞新工作。`test_document_style.py` 记了一张
每文件违规计数基线，断言实际数 ≤ 基线。

基线按计数而不是行号，因为行号随每次编辑漂移。改好一处就把基线减一，
减到 0 就删掉那一行，删空即还清。基线只减不增，这是棘轮。
