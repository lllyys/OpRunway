# skill 开发规范

约束本仓 `skill/<name>/` 下自己写的文件：`SKILL.md` 与 `references/*.md`。
写这些文件时本规则常驻上下文，不需要主动去读。

**这份管形式**（骨架、载体法则、渐进式披露），**句子怎么写归
[doc-style.md](doc-style.md)**（人称、标题、禁用词），那份有可跑的量具：

```bash
python3 .claude/hooks/doc_style_lint.py
```

## 原则

**信息来源可信。** 技术事实只能来自 ATK 源码、CANN 官方文档、任务书、工程公开
接口面、用户明确提供这五处。不确定就标注不确定，不要写成事实。

**默认 Claude 已经很聪明。** 只补它没有的上下文。每一段落地之前过三问
（取自 Anthropic 官方 skill 写作指南）：

1. Claude 真的需要这个解释吗？
2. 能不能假定它已经知道？
3. 这一段值它的 token 吗？

本仓的分界线：**torch、aclnn、精度比对、NPU 编译部署这些它都知道，不用解释**；
本仓自己的约定（三跳来源规则、用例包结构、退出码含义、ATK 某个版本的实测行为）
它不可能知道，必须写。删不掉的判断题是第 2 问——写完一段回头问一次就够。

**渐进式披露。** `SKILL.md` 只写路由与契约，知识放 `references/`，需要时再展开。
可量的两条：`SKILL.md` ≤ 12 KB；**单个阶段的最小载入 ≤ 32 KB**，即 `SKILL.md`
加上那一步链出去的 references。**这是防回涨的护栏，不是要压的指标**——为了压进
预算而把不可跳过的闸挪出路由器，是拿可靠性换数字。单一用途的 skill 实测在
3.5–8.2 KB，多阶段的靠下沉阶段展开就能进预算。量具：

```bash
python3 .claude/hooks/skill_budget_lint.py
```

```bash
wc -c skill/<name>/SKILL.md skill/<name>/references/*.md
grep -n "references/" skill/<name>/SKILL.md
```

**一条链接就是一次强制加载。** 在 S1 里链 S2 才用的 reference，等于让每次跑测
都在 S1 为 S2 的知识付钱。写「见 X.md」之前先答：执行到这一行的 agent，不读 X
会不会卡住？答「到下一步才卡」，这句就该挪到下一步。

**脚本是量具不是知识源。** `SKILL.md` 里出现 `脚本名:行号`，就是在请 agent 去读
那份源码——一个脚本几百行，读一次几千 token。要让 agent 知道的事，写进脚本的
打印与报错，或者写进 `references/`。

**每类内容有固定载体。** 散文只留给结论和取舍，其余各有其位：

| 内容 | 载体 | 反例 |
| --- | --- | --- |
| 脚本做了什么 | 脚本自己的打印与报错 | 命令后跟一段「它跑 X，把结果收敛到 Y」 |
| 为什么这么定 | 表格加「为什么」列，或 `references/` | 指令后追一句因果 |
| 并列的约束或条件 | 列表 | 顿号串成一句 |
| 失败判据与去向 | 判据表：判据 / 长什么样 / 去哪改 | 散落各处的「……时回 S2」 |
| 阶段的输入输出 | 阶段表 | 段落叙述 |

一条命令后面只跟两样东西之一：判据表，或者下一步。脚本干了什么由脚本自己打印。

## SKILL.md 是路由器，不是知识库

骨架如下，没有的章节就不写，不要留空壳：

````markdown
---
name: <与目录同名的 kebab-case>
description: <做什么 + 何时触发>
---

# <Skill 名>

## 入口参数      表格：参数名 | 含义 | 取值约束 | 初值推断
## 前置检查      有强制步骤才写，标明不可跳过
## 主流程        决策树或阶段表；长流程拆进 references/
## 参考资料      链接清单
````

## frontmatter 契约

| 字段 | 要求 |
| --- | --- |
| `description` | 说清**做什么**与**何时用**；只写做什么，agent 选不准 |

与别的 skill 有真实混淆风险时，才在 `description` 里写"……时改用 X"。
没有混淆风险不写——那是反向说明，不是默认格式。

## 目录用途

| 目录 | 放什么 |
| --- | --- |
| `references/` | 按需加载的**泛化**知识：规范、判据、约束、排错。**算子名遮住后句子还成立才留，靠某个算子跑出来的事实进 skill 的 `CLAUDE.md`** |
| `scripts/` | 可执行量具 |
| `assets/` | 模板与样例，供照抄 |

引用深度只许一级：所有 reference 从 `SKILL.md` 直接链出。嵌套引用时 agent 常用
`head -100` 预览而不读全文，拿到的是残缺信息。

## 指令必须具体

**禁止"适当处理"、"根据情况"、"必要时"这类执行者要猜的表达。**

命令、路径、参数、退出码、输出模板一律写死：

| 写法 | 判定 |
| --- | --- |
| 环境不满足时适当处理 | ✗ 执行者要猜 |
| `probe_env.py` 报告非 Phase A 时停在 S1，输出 `阻塞·未生成 @S1` | ✓ |
| 精度不达标就走失败流程 | ✗ 哪个流程、什么输出都没说 |
| 精度未通过时性能状态填 `未执行(精度未通过)`，不跑性能轮 | ✓ |

## 写完自检

- [ ] `description` 说清了做什么与何时用
- [ ] 步骤有输入、处理、输出，执行者不用猜流程
- [ ] 失败、缺输入、环境不可用时的去向写明了
- [ ] 命令、路径、参数、输出格式具体
- [ ] 大段知识在 `references/`，`SKILL.md` 只留路由
- [ ] 每条 `references/` 链接都在真正用得上的那一步，没有前置到更早的阶段
- [ ] `SKILL.md` 里没有 `脚本名:行号` 式的引用
- [ ] 每类内容都在上表指定的载体里
- [ ] 技术事实有来源，未验证项已标注
