# repo-task-doc-write 上手

让 AI 助手帮你把一个算子的开发要求写成任务书。助手出候选，你拍板，出口有一道质量门。

## 前提

只需要 python3，不需要 NPU、CANN、torch，也不需要算子已经存在。

skill 按 [README 的安装](../../../README.md#安装) 装好即可，第三步跳过。

## 第一条消息怎么写

助手会先问「前提三项」，直接在第一条消息里给掉能省一轮：

```text
用 repo-task-doc-write 写 Median 算子的任务书。

工程模式：aclnn算子工程化开发     # kernel直调 / aclnn算子工程化开发 / torch接口
对标基线：torch.median            # 验收侧拿它当真值
提交仓库：https://gitee.com/xxx/ops-nn
已有材料：/home/user/note.md      # 需求描述、对标文档，有多少给多少
输出到：/home/user/task/
```

拿不准就先说算子名，助手会按批次问过来。

## 中途会问你什么

助手按 [八个批次](design.md#五个阶段) 追问，每批都是「候选 + 请你判断准了、缺了还是多了」。

**你的答复原话会被逐字记进 `decisions.json`。** 这是红线 A：agent 的推断不算事实，
只有人拍板的才算。所以别只回「可以」，把理由和边界说出来。

随机数生成类算子会多问一项精度对比策略——CPU 与 NPU 的随机数流通常不一致，
不能默认用 equal 比。

## 常见卡点

- **门禁判红了，想改判据让它过** —— 不行。每条报错都带「不写会怎样」和替代写法，
  先读报错。判据要能指回一条真实缺陷，改判据等于把防线拆了
- **跑完门禁又改了稿** —— `gate_pass.json` 的 sha256 会对不上交付的 md。
  没有匹配的封条就是没过门，改完重跑
- **想给模板加章节** —— 只做加法，不重编号。重编号会把存量任务书的交叉引用全断掉
- **不知道某一节该写多细** —— 看 `references/golden-task-doc.md`，那是一份过了
  全部五层门禁的任务书。不要参照别处的任务书，别处的没有经过本门禁
- **交付前还剩什么要人做** —— `references/manual-checklist.md` 里那五条机器判不了的，
  逐条核对
