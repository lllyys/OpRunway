# repo-task-atk-accept 方案设计

接收封印用例包，在 NPU 上构建并验收待测算子的精度与性能。

设计目标与生成侧一致：**驱动零上下文的 AI 助手独立完成自己负责的阶段。**
验收侧不生成新用例，只在交接包副本上完成 S0 与 S3–S5。

## 阶段

| 阶段 | 做什么 | 出口 |
| --- | --- | --- |
| S0 接收与环境 | 重算封印，核任务书、ATK、接口与环境 | `bundle_intake.json` |
| S3 编译安装部署 | 构建、安装、绑定并跑冒烟 | 冒烟真实通过 |
| S4 精度性能测试 | 执行全量并由量具裁决 | accuracy / performance 结论 |
| S5 输出测试结果 | 汇总报告、证据与复现包 | 换机器可重跑 |

S3 或 S4 失败都不得返回 S2 重生成。封印后的接线改写只能走
`rewire_adapter.py`，且必须保持用例语义不变。

## 边界

验收侧可以读工程的公开接口面、README、设计文档与构建入口；不得用 kernel、host、
tiling 或内部断言设计用例、补预期或给失败归因。装机 CANN 的同名接口也不能替代
待验收工程头文件。

以下判据全部机械化：

- 交接包摘要、任务书与 ATK 版本一致
- PR 头文件签名与任务书声明一致
- 构建、SoC、op_api、ABI 绑定与冒烟通过
- 精度分母、性能状态和最终结论由产物推导

四条架构红线、骨架与共用件纪律见
[开发规则](../../../skill/repo-task-atk-accept/CLAUDE.md)。

## 与生成侧的交接

输入必须是 [repo-task-case-gen](../repo-task-case-gen/design.md) 产出的封印包。
只有任务书时先走生成侧；交接包未封印或摘要不一致时停在 S0，不在验收侧补件。

验收结束交付三类结果：结论、证据与复现包。精度失败时不执行性能；没有性能对比基线时
仍采集待验收算子的绝对耗时，但不判性能通过。

上手步骤见 [quickstart.md](quickstart.md)。
