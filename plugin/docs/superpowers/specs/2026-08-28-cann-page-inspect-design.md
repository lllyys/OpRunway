# 昇腾社区 CANN 页面巡检 skill

**范围：** 新增 `skill/cann-page-inspect`，本仓第三条链路。ATK 与 ops-blas
两条链路一行不动。

替代的人工动作：每天打开 `https://www.hiascend.com/cann`，逐个点页面上的链接，
看内容是否符合预期。

## 页面边界

三个页签，不往下爬。链接数为 2026-08-28 渲染后实测，去掉三页共有的 54 条页头页脚：

| 页 | URL | 正文链接 |
| --- | --- | --- |
| 主页 | `https://www.hiascend.com/cann` | 44 |
| 下载 | `https://www.hiascend.com/cann/download` | 6 |
| 开发 | `https://www.hiascend.com/cann/develop` | 3 |

主页 44 条构成：SIG 会议 22、生态 github 7、gitcode 源码仓与 recipes 6、
版本公告 3、动态新闻 3、站内其余 3。

## 实测事实

全部 2026-08-28 实测。带 ⚠ 的一条是当天先下错结论后被复测推翻的，保留记录。

| # | 事实 | 影响 |
| --- | --- | --- |
| 1 | 站点是 Nuxt 客户端渲染。curl 拿回的 99 KB HTML 只有 40 个 `<a>`，全是页头页脚与 CSS | 取链必须渲染。linkinator 只认服务端 HTML、lychee 不跑 JS，本站直接不可用 |
| 2 | `productbulletins/detail/999999`（瞎编 ID）返回 **200**，`<title>` 与真公告逐字相同 | 状态码与 title 都不能当判据 |
| 3 | 后端接口 `ascendservice/bulletins/front/details/999999` 同样返回 **200** | 接口逆向一并排除 |
| 4 | 渲染后正文可判：真公告 663 字含「发布时间 2026/08/11」，假公告 330 字含**「抱歉，您访问的页面不存在」** | R2 的判据 |
| 5 | 锚文本 / URL 的关键 token 在目标页可对上：公告 `9.2.0-beta.1`→正文、`ops-nn`→title、新闻锚文本→title 逐字相同、`deepseek-v3.2-exp`→title | R3 的判据 |
| 6 ⚠ | gitcode 早晨 curl 返 504、连接重置，当时判为反爬；下午 curl / httpx / curl_cffi 各连跑 3 次**全部 200** | **反爬结论作废**，实为目标站瞬时抖动。对策是重试，不是换客户端 |

**踩坑记录：固定 sleep 会同时误报真假两页。** 等 3.5 秒时真假公告正文都是 285 字空壳，
完全一样；等到 12 秒才分化。等待策略必须是「等到正文关键元素出现，或等到失败标记
出现，二者取先」，不许写死秒数。

## 判据：七条规则

检查项按**问题本身**命名，看名字就知道是什么毛病，不另设严重度列——
表的顺序就是严重度：前四条是「看不到或看错了」，后三条是「内容过时了」。

| 编号 | 检查项 | 判定依据 | 覆盖 |
| --- | --- | --- | --- |
| R1 | 链接打不开 | 三次重试（指数退避）全部失败：DNS / 连接 / 超时 / 4xx / 5xx | 53 条全部 |
| R2 | 页面打开是空白 | 渲染后正文含 `抱歉，您访问的页面不存在`，或正文短于 400 字 | 站内 CSR 8 条 |
| R3 | 跳到了别的页面 | 终点 URL 落在登录页、站点首页或根路径 | 53 条全部 |
| R4 | 打开的不是该内容 | 锚文本或 URL 的关键 token 未出现在目标页 `<title>` 或正文 | 可提 token 的 31 条 |
| R5 | 下载版本与公告不一致 | 下载页「版本选择」的版本号 ≠ 主页最新版本公告的版本号 | 1 组 |
| R6 | 会议已结束仍在展示 | 会议链接 URL 内的日期早于巡检日 | 带日期的会议链接 2 条 |
| R7 | 内容长期未更新 | 最新版本公告距今 > 90 天，或最新动态新闻距今 > 30 天 | 2 组 |

**R3 与 R4 不重叠。** R4 只对能提取 token 的 31 条生效；22 条 SIG 会议链接与
「查看详情」这类锚文本提不出 token，跳到登录页只有 R3 抓得住。

**R7 的阈值是制定的，不是测出来的**，写在脚本顶部的常量区，一行改。

**站内 CSR 白名单**（R2 生效范围，必须渲染才能判）：`/productbulletins/detail/*`、
`/cann/*`。动态新闻 `/zh/activities/dynamic-news/*` 实测是 SSR，`<title>` 直接是
新闻标题，不进白名单。

**R4 的 token 提取规则：** 版本号（`\d+\.\d+\.\d+[\w.-]*`）、gitcode/github 仓库名
（URL 倒数第二段与最后一段）、模型名（URL 路径末段）、新闻标题（锚文本全文）。
提不出 token 的链接不适用 R4，不算通过也不算失败。

**R4 未验证的部分：** 五条正例今天都实测匹配，但**负例（链接可达而名实不符）
今天页面上不存在**，假阳性率未知。上线首周需人工核对 R4 的每一条命中。

## 主流程

四步。每步的失败去向写死，不做「尽力而为」降级。

| 阶段 | 处理 | 失败去向 |
| --- | --- | --- |
| S1 自检 | Chrome 可用、playwright 与 httpx 可导入、三个入口页可达 | 任一不满足即停，不出半份报告 |
| S2 取链 | 渲染三个入口页，滚到底触发懒加载，抽 `<a>` 与锚文本 | 某页取到 0 条正文链接即停并报异常 |
| S3 探测判定 | 站外 45 条 httpx 并发；站内 CSR 8 条走浏览器；跑 R1–R5 | 单条三次重试全失败→R1 命中 |
| S4 出报告 | 读 `.state/baseline.json` 标首次发现日期，渲染 `report.html`，回写状态 | — |

## 产出

```text
<输出目录>/cann-page-inspect/
├── report.html            人看的唯一产出，双击打开，每次覆盖
└── .state/
    ├── baseline.json      每条异常的首次发现日期，用于标「今日新增 / 已连续 N 天」
    ├── last-run.json      本次全量结果，有人质疑结论时拿它对账
    └── run.log            最近一次运行日志，只在报错时看
```

### report.html

单文件，样式内联，不加载任何外部资源——巡检机器可能没网，报告可能被转发。

三段：

1. **结论行** — 巡检时间、目标、`4 条需处置` 或 `全部正常`
2. **规则汇总简表** — 五列：`编号` / `检查项` / `判定依据` / `覆盖` / `命中`。
   七行对应 R1–R7，命中为 0 的行置灰。命中数着色区分前四条与后三条，不设图例
3. **问题明细表** — 一张表按规则编号排序，列：`编号` / `位置` / `实测` / `期望` /
   `首次发现` / `复核`

**正常条目一条都不列**，只在页脚给一行统计，以及一行「N 条链接经重试后通过」——
重试次数不单独成类，但要留痕。全部正常时明细表整个不渲染。

实测列要具体到能直接动手：不写「链接失效」，写
`HTTP 200，渲染后正文 330 字，含「抱歉，您访问的页面不存在」`。

## 工具选型

选型结论经过实测比较，不是「本机现成就用」。

| 层 | 选定 | 排除的方案与实测理由 |
| --- | --- | --- |
| 取链与站内渲染 | `playwright`（`channel="chrome"` 复用本机 Chrome，不下载 chromium） | 浏览器 MCP：光工具定义就约 13.7k tokens 常驻上下文，价值在交互式驱动，而本任务是无人值守脚本，agent 全程不看网页内容。Stagehand / browser-use 同理 |
| 站外探测 | `httpx` 并发 | `curl_cffi` / Patchright / camoufox：实测三个域名均无 TLS 指纹门禁，httpx 结果与 curl_cffi 逐字节相同且更快，零收益 |
| 链接检查 | 自写 | lychee 只返回状态码，判不了事实 2 的软 404；linkinator 看不见 JS 注入的链接 |

**低 token 的来源不是选哪个库，是网页内容一个字都不进 agent 上下文。**
脚本吐 `report.html`，agent 只读退出码与结论行。

## 收敛：砍掉的东西

逐条问「砍掉它会怎样」，第一轮砍十项，复审找回两项半误删，最终砍七项。

| 砍掉 | 为什么 |
| --- | --- |
| 内容漂移 / 基线 diff | 噪声压倒信号：gitcode 正文含 Star 数、Issue 数、最后提交时间，天天变；且漂移≠错误，把判断题推回给人，正是本 skill 要替代的动作。其意图由 R4 承接 |
| LLM 语义判读 | 七条规则全是确定性判据，没有灰区需要模型判 |
| 「疑似反爬」分类 | 事实 6 推翻。抖动用重试解决，报告页脚留一行重试统计即可 |
| `curl_cffi` 等指纹伪装 | 实测无 TLS 门禁，零收益 |
| 浏览器 MCP | 无人值守脚本不需要交互式驱动，13.7k tokens 常驻是纯浪费 |
| 按日期留档报告 | 人关心「现在坏没坏」，不是三周前坏过什么 |
| 下载页交互选型矩阵 | 用户明确排除 |
| 定时调度 | skill 只管跑一次，每日触发交给 cron / launchd |

复审找回的三项，记录误删原因以免重犯：

| 找回 | 当初砍掉的理由错在哪 |
| --- | --- |
| R7 内容长期未更新 | 理由是「阈值是拍的、当前不会触发」。但 R5 当前命中也是 0 却留着——同一标准得出相反结论；且时效是用户明确选的四类之一，拿实现困难缩范围 |
| R3 跳到了别的页面 | 理由是「R4 能覆盖」。但 R4 只对能提 token 的 31 条生效，22 条会议链接与「查看详情」提不出 token，跳登录页无人能发现 |
| `.state/last-run.json` | 理由是「与基线同源」。基线语义后来改成只存首次发现日期，这条理由随之失效 |

## 实现规模

一个脚本一条命令：

```bash
python3 skills/cann-page-inspect/scripts/inspect.py --out <输出目录>
```

`SKILL.md` 保持路由器形态：入口参数表、这一条命令、五条规则的判据表、失败去向。
不写脚本内部逻辑——脚本干了什么由脚本自己打印。

## 登记

1. 建 `skill/cann-page-inspect/`，目录名与 frontmatter `name` 逐字相同
2. 按 `.claude/rules/skill-style.md` 写 `SKILL.md`
3. `.claude-plugin/plugin.json` 的 `skills` 数组加 `"./skill/cann-page-inspect"`——
   **漏了这行 skill 静默不加载**
4. `README.md` 首表与仓根 `CLAUDE.md` 首表各加一行，说明第三条链路

**不用 `repo-task-` 前缀。** 它不是 repo task，套前缀会让 description 的触发判断
和另外五个 skill 撞车。
