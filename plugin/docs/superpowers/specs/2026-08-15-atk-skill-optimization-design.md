# ATK 社区验收技能优化设计

## 目标

在不改变验收判定算法、结构化产物和现有脚本输出格式的前提下，降低技能触发后的上下文占用，消除规则重复，并让 agent 能按当前阶段读取最小必要信息。

## 现状问题

- `SKILL.md` 497 行，同时承载流程、规则、命令和参数路由。
- reference 约 3,600 行；流程门禁、设备选择、性能前置条件和 CLI 约束在多个文件重复。
- `plugin-authoring.md` 和 `case-design.md` 混合规范、解释、历史依据和示例，单次读取粒度过大。
- reference 之间互相链接，agent 需要跨文件追链才能完成局部决策。
- Markdown 手写脚本参数，易与 argparse 漂移。
- 测试和 `__pycache__` 混在技能发布目录，增加分发体积但不提供执行知识。
- “禁止读取 ATK 源码”与部分 reference 中的源码路径、行号和考古说明边界不清。

## 设计

### 1. 主技能作为路由器

将 `SKILL.md` 压缩为四部分：触发说明、全局不变量、阶段状态机、按决策点的 reference 路由。每个阶段只列输入、调用入口、产物和停止条件，不重复 reference 的细节。

主文档目标不超过 180 行，并保留 imperative/infinitive 表达。十个现有阶段不改变，只减少每阶段的叙述和重复。

### 2. Reference 按决策域拆分

保留现有文件名作为兼容入口，但将正文收敛为以下五个直接路由域：

- intake：输入、基线、接口模式和阻塞项。
- design：覆盖策略、YAML 契约和插件选择。
- adapter：生成器、运行时参数和 ACLNN 适配契约。
- execution：环境、部署、ATK 命令、冻结和执行门禁。
- reporting：解析、裁决、性能选样和交付。

每个 reference 只定义自己的事实；跨域共享规则移动到 `acceptance-policy.json` 或一份短的公共契约。reference 不再互相链接，主文档负责导航。

### 3. 规则单一事实源

为重复规则建立稳定的规则 ID，并在 Markdown 中只引用 ID。机器可验证内容继续由 `acceptance-policy.json` 定义；文档不复制比较器、排除原因、后端映射和裁决门禁的完整列表。

### 4. 命令契约收敛

保留现有脚本和 CLI 行为。删除主文档中的完整参数表，改为阶段调用表；命令示例只保留每阶段最小必需参数。增加文档检查，比较脚本 argparse 的公开选项与路由表，防止新增漂移。

### 5. 发布边界

技能目录只发布运行所需的 `SKILL.md`、reference、脚本和必要资产。测试移到仓库测试目录；删除 `__pycache__`，并补充忽略规则。现有测试继续运行，但不作为技能运行时资源。

### 6. 证据边界

将 reference 中的源码路径和历史考古说明改成已固化的行为事实；维护依据不进入运行时 reference。验收期间仍禁止读取待测源码和 ATK 内部实现，受控探测规则只保留触发条件、产物和回写责任。

## 兼容性和验收标准

- 所有现有脚本的 CLI、退出码、JSON 字段和报告结构保持不变。
- 现有技能测试全部通过。
- `SKILL.md` 不超过 180 行。
- 每个 reference 只由 `SKILL.md` 直接路由，不出现 reference 到 reference 的 Markdown 链接。
- 规则重复检查只允许白名单中的术语复现。
- 文档中的脚本调用与脚本 `--help` 选项一致。
- 技能发布内容不包含测试缓存和 Python 字节码。

## 实施顺序

1. 压缩主技能并建立阶段路由。
2. 收敛 intake/design/execution/reporting 的重复规则。
3. 拆分 plugin-authoring 的按需内容，保留兼容入口。
4. 统一命令路由和文档 lint。
5. 清理发布边界，运行全量测试和文档检查。
