# 快速上手

本文介绍怎么让 AI 助手用这套流程验收一个算子。

流程本体由助手执行，你的工作是把它缺的信息一次给全。

## 开始之前

验收在装有 NPU 的机器上进行，该机器需要具备三样东西。

- **CANN** 已安装，且 `set_env.sh` 可以 source
- **ATK 与验收流程** 已按 [README 的安装三步](../README.md#安装) 装好
- **待验收算子工程** 已下载到本地，收到的是 PR 时先归约成本地工程

开始之前请亲自跑一次下面这条命令确认 ATK 可用。

```bash
atk case --help
```

真机上出现过 ATK 缺少 pytz 的情况：包导得进来，命令一调就报错，
任务在 0 秒内「正常结束」，产物是空的。

## 你必须显式告诉助手的信息

助手不猜、也探测不出下面这些，缺一项就会停下来问你。

一次说清可以省掉来回确认。

- **用哪张卡** 助手只记录你给的编号，不做可用性预检
- **CANN 装在哪** 机器上装了多份 CANN 时必须指明本轮用哪一份
- **算子工程在哪** 给本地绝对路径，签名只从这个目录里的头文件读
- **任务书在哪** 精度与性能的判定标准全部来自任务书，没有它无法验收
- **提交形态** pytorch、aclnn、kernel、triton 或 atb 之一

## 第一条消息怎么写

把上面五项一次写进第一条消息，例如：

```text
用 repo-task-atk-test 验收 aclnnMedian。

算子工程：/home/user/ops-nn
任务书：/home/user/task/median.md
用 device 0，CANN 在 /usr/local/Ascend/ascend-toolkit/latest
提交形态是 aclnn
```

助手会据此建立工作目录，然后按阶段推进。

## 验收会怎么走

验收分五个阶段，按顺序完成，前一阶段不通过不进入下一阶段。

- **S1 任务书解读** 把任务书变成可核验的约束，并记录本机环境
- **S2 用例生成** 产出测试配置与用例，本阶段结束时冻结输入
- **S3 编译安装部署** 构建并安装待验收算子，直到一条冒烟测试真的跑通
- **S4 精度性能测试** 跑全量测试，裁决精度，记录性能
- **S5 输出测试结果** 给出报告、结论与可复现的验收包

工作目录建在算子工程的同级，不建在工程内部。

## 助手中途会问你什么

有两类问题助手必须问，答复会被记进证据里。

**任务书没写清的地方。**
助手会把它标成待确认项，确认之前不进入下一阶段。

**要不要测另一套语义。** 同一个接口在某个出参传空时换算法这类情况，
默认不测，你明确要求才测。

## 你会拿到什么

验收结束后，工作目录里有三样可直接使用的产物。

- **结论** 精度是否达标、性能是否达标
- **证据** 环境指纹、接口事实、冻结输入的校验和
- **复现包** 换一台机器可以重跑本轮验收

## 常见卡点

**助手说找不到签名。**
签名只从算子工程目录里的头文件读，不去 CANN 装机目录找同名接口。

社区算子与官方接口重名很常见，装机目录里那份是另一份代码。

工程里确实没有时，请补齐工程或说明情况，不要让助手换个目录继续找。

**测试跑完但产物为空。**
先确认 `atk case --help` 在该机器上能正常返回。

**助手想回头重新生成用例。**
S2 结束后输入已冻结，S3 或 S4 失败都不允许回到 S2 重新生成。

这是有意为之，防止用测试配置去迁就算子的实际表现。
