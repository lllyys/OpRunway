# 自定义执行方式

## 扩展目标

自定义执行方式用于控制测试用例在不同后端上的实际调用逻辑。当默认的 `function`、`method`、`tensor` 执行方式无法满足算子调用需求时，可以通过自定义执行方式适配算子。基础任务执行流程见 [任务执行](<../01 基础操作/任务执行.md>)。

本文同时承载 ACLNN 执行适配和 ACLNN 自定义 API 编写内容。

## 适用场景

以下情况适合实现自定义执行方式：

- 算子调用方式不能直接通过 `eval(self.api_name)(*args, **kwargs)` 表达。
- 不同后端需要不同执行逻辑。
- 执行前需要根据输入数据初始化中间对象。
- 性能测试时需要排除部分预处理耗时。
- ACLNN 算子需要构造 aclnn 输入、workspace、executor 或输出参数。
- 标杆输出与待测输出的结构不一致，需要自定义返回结果。

## 接口说明

自定义执行方式需要继承 `BaseApi`，并通过 `register` 注册名称。注册名称需要与用例设计文件中的 `api_type`、`aclnn_api_type` 等字段一致。

常用接口如下：

| 接口 | 说明 |
| --- | --- |
| `__init__` | 初始化执行器，可保存算子名称、设备、输出配置等信息。 |
| `init_by_input_data` | 根据输入数据做执行前初始化，不计入 e2e 性能耗时。 |
| `__call__` | 核心执行逻辑，返回算子输出。 |
| `cal_cube_computation` | 自定义 cube 计算量，用于 TFLOPS、MFU 等指标。 |

## 基础执行方式扩展

示例：

```python
import torch

from atk.configs.dataset_config import InputDataset
from atk.configs.results_config import TaskResult
from atk.tasks.api_execute import register
from atk.tasks.api_execute.base_api import BaseApi


@register("sample")
class SampleApi(BaseApi):
    def __init__(self, task_result: TaskResult):
        super().__init__(task_result)
        self.my_val = None

    def init_by_input_data(self, input_data: InputDataset):
        if self.device == "cpu":
            self.my_val = 1

    def __call__(self, input_data: InputDataset, with_output: bool = False):
        if not with_output:
            eval(self.api_name)(*input_data.args, **input_data.kwargs)
            return None

        if self.device == "npu":
            import torch_npu
            output = eval(self.api_name)(*input_data.args, **input_data.kwargs)
        elif self.device == "cpu":
            output = eval(self.api_name)(*input_data.args, **input_data.kwargs)
        elif self.device == "gpu":
            output = eval(self.api_name)(*input_data.args, **input_data.kwargs)
        else:
            raise RuntimeError(f"Unsupported backend: {self.device}")

        return output
```

在用例设计文件中配置：

```yaml
api_type: sample
```

执行任务时传入插件：

```shell
atk pytorch result/op_max/json/all_op_max.json --plugin function_sample.py
```

## 输入数据访问方式

`InputDataset` 常用字段如下：

| 字段 | 说明 |
| --- | --- |
| `args` | `inputs` 中未配置 `name` 的位置参数。 |
| `kwargs` | `inputs` 中配置了 `name` 的关键字参数。 |
| `method_args` | `method_inputs` 中未配置 `name` 的位置参数。 |
| `method_kwargs` | `method_inputs` 中配置了 `name` 的关键字参数。 |
| `tensor_args` | `tensor_input` 对应的调用对象。 |

## ACLNN 执行方式适配

ACLNN 算子通常需要处理以下内容：

- 根据 aclnn 接口签名构造输入参数。
- 调用 `GetWorkspaceSize` 获取 workspace 和 executor。
- 根据输出参数要求构造输出 Tensor。
- 调用实际 aclnn API。
- 将输出结果转换为 ATK 可比较的数据结构。

用例设计中可配置 ACLNN 相关字段：

```yaml
api: pytorch
api_type: function
aclnn_api_type: custom_aclnn
name: torch.max
aclnn_name: MaxDim
```

执行时使用 ACLNN 后端：

```shell
atk aclnn all_aclnnMaxDim.json --plugin function_custom_aclnn.py
```

如需开启 ACLNN 参数校验，可使用：

```shell
atk aclnn all_aclnnMaxDim.json -cp
```

## ACLNN 自定义 API 编写

ACLNN 自定义 API 通常按以下阶段组织：

| 阶段 | 说明 |
| --- | --- |
| 入参处理 | 在 `init_by_input_data` 中根据 ATK 输入数据构造 aclnn 需要的数据结构。 |
| 算子执行 | 在 `__call__` 中调用 aclnn 接口。 |
| 出参处理 | 将 aclnn 输出转换为 PyTorch Tensor 或 ATK 可比较对象。 |
| 参数校验 | 按需开启签名校验，检查 YAML、C++ 接口和执行器实现是否一致。 |

基础结构示例：

```python
from atk.configs.dataset_config import InputDataset
from atk.tasks.api_execute import register
from atk.tasks.api_execute.base_api import BaseApi


@register("custom_aclnn")
class CustomAclnnApi(BaseApi):
    def init_by_input_data(self, input_data: InputDataset):
        # 根据输入构造 aclnn 所需参数、输出 Tensor 或 workspace 信息。
        pass

    def __call__(self, input_data: InputDataset, with_output: bool = False):
        # 调用 aclnn GetWorkspaceSize 和实际执行接口。
        # 返回需要参与精度比较的输出。
        pass
```

如果标杆输出与 ACLNN 输出数量不同，可在自定义执行插件中只返回需要比较的输出，或配合自定义精度比较处理复杂输出结构。

## 单标杆场景的输出构造

部分 ACLNN 单标杆场景需要跳过低精度执行，直接构造输出 shape 和 dtype。可通过 `self.task_result.is_get_output_task` 判断当前是否处于获取输出信息阶段：

```python
from atk.configs.dataset_config import InputDataset
from atk.tasks.api_execute import register
from atk.tasks.api_execute.base_api import BaseApi


@register("custom_function")
class FunctionApi(BaseApi):
    def __call__(self, input_data: InputDataset, with_output: bool = False):
        if self.task_result.is_get_output_task:
            output = torch.ones([6, 7, 8], dtype=torch.float16)
        else:
            output = eval(self.api_name)(*input_data.args, **input_data.kwargs)
        return output
```

## 插件加载方式

执行插件文件建议命名为 `function_*.py`。通过 `-p` 或 `--plugin` 传入自定义执行文件：

```shell
atk pytorch result/op_max/json/all_op_max.json --plugin function_api.py
```

也可以传入插件目录：

```shell
atk pytorch result/op_max/json/all_op_max.json --plugin ./plugins
```

如果 `case_file` 所在目录下只有一个 `function_*.py`，简化入口会自动加载该文件，普通场景可以不显式传 `--plugin`。

## 调试建议

- 确认 YAML 中的 `api_type` 或 `aclnn_api_type` 与注册名称一致。
- 确认插件路径已经通过 `--plugin` 传入任务执行命令，或确认 case 文件所在目录下存在唯一的 `function_*.py`。
- 如果输入取不到，优先检查 YAML 中 `name` 是否为空，以及参数在 `args` 还是 `kwargs`。
- 如果 ACLNN 参数校验失败，优先检查 C++ 接口签名、YAML 输入参数和自定义执行器参数处理是否一致。
- 如果输出数量不一致，应明确 `outputs` 配置或实现自定义精度比较；自定义精度比较可参考本文“ACLNN 自定义执行器”和“调试建议”中的输出比较处理说明。
