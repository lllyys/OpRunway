# 接收：建现场与探环境

对应 A1。**A0 那道人工确认的闸在 `SKILL.md` 里**，没拿到两个路径的确认之前不要走到这一步。

## A1 接收与环境

```bash
mkdir -p <输出目录>/<op>-verify/{input,work/stage,work/evidence}
cp -r <用例包>/* <输出目录>/<op>-verify/input/
cd <输出目录>/<op>-verify/work && <python> <skill>/scripts/probe_env.py \
    --op <op> -o stage/env.json --write-env-sh evidence/env.sh
```

**不用先手工 source CANN 环境**，`probe_env.py` 自己找 `set_env.sh` 后重入。

| 退出码 | 含义 | 去向 |
| --- | --- | --- |
| 0 | atk、torch_npu、CANN、NPU 全可用 | 进 A2 |
| 2 | 缺件 | 停止，输出 `阻塞·未验收 @A1`，列出 `stage/env.json` 的 `missing` |

**在 `input/` 副本里验收，不改它的任何文件**，也不改原用例包。

**手上是生成侧的用例包**就 `cp -r <用例包>/*`，标杆是冻结的 `golden/`，按本文走。
**手上是任务书自带的跑测件**就 `cp -r <自带件目录> input/kit/`，标杆是自带件的节点
当场算，`facts.json` 由本步从任务书写出来——**整条改走
[kit-acceptance.md](kit-acceptance.md)**，字段表也在那份里。
