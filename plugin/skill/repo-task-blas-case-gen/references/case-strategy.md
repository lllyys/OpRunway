# 覆盖策略

用例设计的目标是**发现算子缺陷**，不是把通过率做到 100%。一批全绿但从没碰过
tiling 切分边界的用例，没有验收价值。

本文说明每条轴覆盖什么、为什么。字段语法与机械规则见
[facts-schema.md](facts-schema.md) 与 [csv-and-blocks.md](csv-and-blocks.md)，本文不重复。

## 四条覆盖轴

BLAS 算子的缺陷集中在这四处：

| 轴 | 缺陷长什么样 | 覆盖手段 |
| --- | --- | --- |
| dtype | 新增 dtype 没走通、混合精度选路错、复数实虚部处理漏 | profile 全覆盖，任务书点名的 dtype 必测 |
| shape | tiling 切分边界算错、尾块漏、前导维 padding 处理错、压缩维越界 | 维度档用 2^n 与 2^n±1 边界对 |
| 规模 | UB 装不下时的循环切分、多核切分、尾核处理 | 按字节量级覆盖小、中、大 |
| attr | 枚举分支漏、inc=0/负步长没归一化、边界标量分支漏 | 枚举全组合，标量与 inc 覆盖到两端与 0 |

### dtype：任务书点名的必测

算子的 dtype 要么由接口固定（`sasum` 恒 float32），要么由 `dtype_profiles` 给出
（`AxpyEx` 的 fp16/fp32/bf16）。社区任务书基本是「给已有算子扩展支持某几种 dtype」，
那几种就是缺陷最可能在的地方。

**新增 dtype 必须各进一个 profile，原有 profile 不能删。** 任务书写「保持原有功能不变」，
漏测原有 dtype 就是漏回归。复数算子的实部、虚部要在 fill 与标量档里都出现，不能只测纯实。

### shape：2^n 与 2^n−1 边界对

tiling 按块切分，缺陷藏在「刚好一块」「差一个元素」「多一个元素」这三处。维度档在每个
代表性 2^n 处给出三元组把这三处夹住，默认取值：

```text
[1, 2, 3, 15, 16, 17, 63, 64, 65, 255, 256, 257, 1024]
```

纯向量长度再加一个大值（`100003`），覆盖归约类算子（asum/nrm2/dot）的累加路径。这份取值
是通用起点，靠 pairwise 两两组合控制规模；算子要更密的边界就在 `cases.dim_tiers` 里换档。
算子文档写了维度上限（如「维度 [1,8]」）就按它裁剪，不要超上限去测——那测的是参数校验
不是计算。gemm/herk 类的压缩维 k 另取 0，覆盖空累加与尾块。

**不要只留圆整 2^n、不夹 2^n±1。** 差一个、多一个的尾块 bug 正是这样漏掉的。

### 规模档：字节数，不是元素数

同样 65536 个元素，int8 是 64 KB，complex64 是 512 KB，落在算子搬运能力的不同区间。规模
按字节量级覆盖三档：

| 档 | 字节 | 覆盖什么 |
| --- | --- | --- |
| small | < 32 KB | 单核单次搬运装得下 |
| medium | 32 KB – 2 MB | UB 装不下，要循环切分 |
| large | ≥ 2 MB | 多核切分、尾核处理 |

BLAS 不另设按字节配比的机制：维度档从 1 跨到 1024（方阵 fp32 即 4 B 到 4 MB，向量到十万级），
pairwise 天然把用例铺到三个字节量级；`cases.max_footprint_bytes`（默认 4 GiB）只对超预算的
行做安全剪枝，不是覆盖机制。窄 dtype（int8）想摸到 large，就调大 `cases.dim_tiers` 的上界。

**不要为了跑得快砍掉 large 档**——那等于宣布不测多核切分。tiling 边界缺陷在 2^n±1 的小张量
上就能暴露，但多核与尾核切分只有 large 覆盖得到。

### attr：值域两端与 0

BLAS 的 attr 是枚举、标量与步长，三类都要覆盖到边界：

- 枚举（uplo/trans/side/diag）全组合进 L0，pairwise 覆盖其余组合。
- 实标量档含 `0.0`（空操作，只保留 beta·C）、`1.0`、`-1.5`；复标量含纯实与含虚部两类。
- inc 档默认 `[1, 3]`；任务书或 README 允许 `inc=0` 或负步长时，用 `cases.inc_tiers` 显式加入。
- 有 ld 的算子用 `pad` 档制造前导维大于行数的非对齐布局。

## 数据填充：覆盖到极值

fill 词表（见 [aclblas-conventions.md](aclblas-conventions.md)）要在正态、零、交替符号和极值
之间铺开，缺陷类型才碰得到：

| fill | 碰什么缺陷 |
| --- | --- |
| `RANDOM_NORM_1` | 常规数值路径 |
| `VALUE_NORM_0` | 全零输入、beta·C 独立性 |
| `RANDOM_ALTER` | 交替符号、累加抵消 |
| `RANDOM_EXTREME` | 饱和、溢出、非规格化 |

算子文档写了定义域限制（如三角求解要求非奇异、对角占优）时以文档为准，用矩阵构造类型
（`conditioning`）表达，不要套通用 fill。

### 填充上不要做的事

| 反模式 | 后果 |
| --- | --- |
| 只用 `RANDOM_NORM_1` 一种 fill | 极值与全零路径零覆盖 |
| 复数只测纯实标量 | 虚部处理缺陷撞不到 |
| 用工程 kernel 的容差反推数据范围 | 拿被测实现当判据 |

## 用例规模

目标 **150–400 条**。少于 100 覆盖不住四条轴；多于 500 精度轮拖得久，而增加的用例大多是同一
等价类的重复。维度档变宽后 pairwise 行数自然上升；某算子偏少时，先扩 `cases.dim_tiers` 或补
`edge_cases`，不要靠缩档把数字做小。

这个条数只约束**精度全量**（非 `TC_PF_` 前缀；`TC_PF_` 是性能用例块前缀，四块见 csv-and-blocks.md）。性能子集由 `perf.rows` 单独给出，不计入。

| 用途 | 条数 | 前缀 |
| --- | --- | --- |
| 精度全量 | 150–400 | 非 `TC_PF_` |
| 性能子集 | 由 `perf.rows` 决定 | `TC_PF_` |

## 等价类剪枝 = pairwise

同一等价类多测几十条不增加发现缺陷的概率，把额度让给别的轴。BLAS 把枚举 × 尺寸 × 标量档 ×
fill × ld 的全叉积用**确定性 pairwise** 压到两两组合覆盖：

| 可以合并的 | 理由 | 怎么做 |
| --- | --- | --- |
| fp16 与 bf16 | 内核多半统一转 fp32 计算，走同一条路径 | 用 profile 分档，不各自堆满 |
| 中间尺寸 24/48/96 | 与相邻 2^n 同一等价类 | 维度档不逐个列 |
| 多个枚举/标量的全组合 | pairwise 两两覆盖即可 | 生成器自动做，不手写全组合 |

**不能合并的**：任务书点名的新增 dtype、文档写了特殊分支的取值、约束边界本身、每个枚举组合的
最小合法尺寸（L0 必须全覆盖）。

## 必须单独构造的场景

有些缺陷靠 pairwise 随机组合撞不到，要在 `edge_cases` 或 `cases` 里显式给：

| 场景 | 何时要 | 怎么构造 |
| --- | --- | --- |
| 退化维 | 文档写维度可为 0 或 1 | `edge_cases` 把维度 `set` 成 0/1，expect 按约定表 |
| 可空指针两态 | 参数 `nullable` | `edge_cases` 给 `null<Name>=1`，正例默认非空 |
| 前导维 padding | 有 ld 参数 | ld 档的 `pad` 使 ld > 行数，破坏对齐 |
| 非连续访问 | 有 inc 参数且任务书未排除 | `cases.inc_tiers` 含 >1 的步长 |
| 压缩维边界 | gemm/herk 类有 k | k 取 0 与 2^n±1，覆盖空累加与尾块 |
| 大规模张量 | 规模档缺 large | 调大 `cases.dim_tiers` 上界，让方阵字节量级到 2 MB 以上 |

## 不要做的事

| 反模式 | 后果 |
| --- | --- |
| 为提高通过率缩小维度档 | 测不到 tiling 边界，验收失去意义 |
| 把跑失败的用例从 CSV 删掉 | 掩盖算子缺陷 |
| 用工程 kernel 里的 assert 反推取值范围 | 拿被测实现当判据，写错的 assert 永远测不出 |
| 维度档只留圆整 2^n、不夹 2^n±1 | 差一个/多一个的尾块 bug 漏测 |
| 只测新增 dtype 不测原有 profile | 漏回归，而任务书要求「保持原有功能不变」 |
| 为跑得快砍掉 large 档 | 等于宣布不测多核切分 |
