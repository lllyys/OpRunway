# 两趟的边界：忠实趟能做什么、探索趟能注入什么

P3 执行前读一次，把边界钉住。这份的存在理由是：**探索的诱惑在每一步都会出现**——
你几乎总能想出一个绕过办法，而用出来就把文档的缺陷盖住了。

## 对照表

| | 忠实趟（P3，默认，主结论） | 探索趟（P4，按需，补充） |
| --- | --- | --- |
| 能做什么 | **只做文档明写的操作** | 可注入修复让流程往下走 |
| 不能做什么 | 装依赖 / source 环境 / 加 flag 或 env / 改命令 / 清缓存 / 换工具 / 重试 / 找替代命令——**一律禁止，哪怕明知解法** | **只能注入忠实趟已写进缺陷清单的「修订建议」**（source / soc / proxy 这类有据的最小修复）；**仍不许任意 workaround**（改算子源码、换命令绕过、瞎试参数） |
| 文档笔误 | **照笔误执行**，把笔误当缺陷记下，不修 | 同左，注入修订后重跑并记录 |
| 文档歧义 / 缺步 | 不替它猜、不补全 → 记缺陷，**卡住即停** | 找不到有据修复 → 止于该步 |
| 非文档原因（机器 / 驱动 / 设备） | —— | **不算文档坑**，如实标注、不硬凑，跑不通就收尾 |

两趟共守：不假定仓名 / 路径 / 文档 / SOC；不凭空捏造报告，失败必 grep 真实日志；
CANN 默认已装好，用机器现成的。

## 起始状态约定

- **CANN 默认已装好**，永远当作已满足的前提。本 skill 不负责装或换 CANN。
- 文档「前提条件 / 环境要求」一节声明的（CANN、NPU、仓已 clone 等）**均假设已满足**。
- 例外：文档**要求**某具体前提（如某 CANN 版本）而机器实际不符 → 记为「前提不符」缺陷，
  但**不去装、不去换**——那是探索。

## 与兄弟 skill 的边界

| 需求 | 用谁 |
| --- | --- |
