## 真机验证过的事实

全部在 `https://www.hiascend.com/cann` 实测，日期 2026-08-28。改判据前先看这张表——
其中五条各自否掉过一种看起来合理的做法。

| 事实 | 数据 | 否掉了什么 |
| --- | --- | --- |
| 站点是 Nuxt 客户端渲染 | curl 拿回 99 KB HTML 只有 40 个 `<a>`，全是页头页脚与 CSS；SSR payload 10 KB 只有 footer 友链 | 不渲染的链检器（lychee、linkinator）在本站不可用 |
| 假 ID 页面与真页面状态码、title 逐字相同 | `productbulletins/detail/999999` 返回 200，`<title>` 与真公告一致 | 状态码判活、title 判活 |
| 后端接口对不存在的资源也返回 200 | `ascendservice/bulletins/front/details/999999` → 200 | 接口逆向路线 |
| 空壳与图文页字数几乎相同 | 失效页空壳正文 330 字；`/cann/contrib-guide` 是正常图文页、352 字，等 30 秒也不变 | **用正文字数判空壳** |
| 渲染未完成时真假页正文完全一样 | 站内 CSR 页渲染中途空壳约 285 字，真假两页在此刻不可区分 | **固定 sleep 等渲染**（阈值 260 时三条版本公告全部误报） |
| gitcode 对命令行客户端返限流码 | `gitcode.com/cann/ops-transformer` 三次 httpx 全 418，浏览器复核 200 正常 | 把 4xx 一律判成链接失效 |
| gitcode 的 504 是抖动不是反爬 | 早晨 curl 504/连接重置；同日 curl、httpx、curl_cffi 各三次全部 200 | 引入 curl_cffi 等 TLS 指纹伪装（零收益） |
| 动态新闻页是 SSR，发布时间有明确标签 | 正文含 `发表于 2026/02/10`，httpx 直取即可 | 把新闻页也放进 CSR 渲染白名单 |

## 取链稳定性（2026-08-29 实测）

首轮之后暴露的一组事实，全部在同一天同一站点测出：

| 事实 | 数据 | 否掉了什么 |
| --- | --- | --- |
| 固定滚动预算会拿到半截页面 | 同一个主页在不同轮次取到 40 / 92 / 115 条，`<a>` 总数随渲染进度变 | **`for _ in range(12)` 式的固定滚动取链** |
| 调大超时不治塌陷，只让失败更贵 | `NAV_TIMEOUT_MS` 45000→90000、`SETTLE_TIMEOUT_MS` 20000→45000 后链接数仍是 40，失败路径从 3m44s 涨到 6m59s | **把塌陷当成「时间不够」** |
| 塌陷时脚本原本不停机 | 主页/下载塌成 40 条时三页共有集合从 54 缩到 35，正文链接 22 > 0，`die()` 不触发，照常出报告、退出码正常 | **把停机判据挂在「三页去重后总数为 0」上** |
| 改成稳定判据后取链恒定 | 连续三轮 115 / 72 / 70 条，正文 54 条，无一轮波动 | — |

塌陷本身是间歇性的，**原因尚未测到**：失败当轮单独用 playwright 直连同样三页，
`goto` 5.5s、45 条链接 7.7s 到位；事后按脚本原样时序复跑也没复现。
怀疑是 `<head>` 里第三方阻塞脚本吊住导致 DOMContentLoaded 不触发，
排查手法见 `references/troubleshooting.md`，**是待测项不是结论**。

## 巡检范围（2026-08-29 扩到 19 个页签）

原来只测主页/下载/开发三个页签，实测站点顶部导航共 **19 个 `/cann/*` 入口**，
漏掉的 16 个里包括「学习」「算子库」「文档」这些内容最多的页。扩全后：

| 事实 | 数据 | 否掉了什么 |
| --- | --- | --- |
| 子页签不是链接，点击不改 URL | `/cann/aol` 四个子库是 `li.o-menu-item > div > span`，无 href；点击前后 URL 不变 | **按 URL 爬取的深度优先方案**——这类页面靠 URL 爬永远只拿得到默认选中的那一个 |
| 不点子页签就漏掉大部分内容 | `/cann/aol` 只有 ops-math 8 条在 DOM 里，ops-cv / ops-nn / ops-transformer 各 0 条；逐个点开后 77 → 111 条 | **「渲染完就取链」** |
| 有子页签的页不止算子库 | 算子库 4 个、通信库 2 个、领域加速库 2 个、开源项目列表 10 个 | 只给算子库开特例 |
| 扩全后链接量 6 倍 | 正文链接 54 → 336 条，一轮 7 分 11 秒 | — |
| 塌陷概率随一轮内持续负载升高 | 19 页 4 并发跑到第 2 分钟时 3 页塌成 37 条；同样 3 页单独重取全部正常（70/119/79），3 页 4 并发也不塌 | **靠调超时解决塌陷**；有效旋钮是 `PAGE_WORKERS` |
| `mailto:` 会被判成链接失效 | 社区治理页两个联系邮箱，httpx 报 `UnsupportedProtocol`，A1 命中 2 条假阳性 | **把所有 `<a href>` 一律送进探测** |
| 单条链接的探测异常会掀掉整轮 | `settle()` 中页面自己跳转，`Execution context was destroyed` 未捕获，7 分钟的一轮直接崩掉、不出报告 | **只在 `goto` 外面包 try** |

## 代码仓软 404（2026-09-08 实测）

代码仓链接走浏览器探测时，gitcode 对「不存在的路径」返回 200 而非 404，页面能开但文件查看器
兜底显示「加载失败，请刷新重试」。用户要求把这种软 404 也识别出来。初版把「请刷新重试」直接当
判据，一轮误报 7 条——全是真实存在的 `tree/` 目录链接。逐条浏览器复核后摸清行为：

| 事实 | 数据 | 否掉了什么 |
| --- | --- | --- |
| 不存在的路径（文件或目录）都重定向到 blob/ | `tree/master/examples/NONEXIST_dir_xyz` 与拼错的 `role1-…md` 都 200 且落地 `blob/…`，正文含「加载失败，请刷新重试」 | 把「加载失败」当成目录/文件共用的软 404 判据 |
| 存在的目录留在 tree/，列表是 AJAX 懒加载 | 7 条 `tree/master/examples/…` 目录真实存在，单开浏览器 2.4s 列表就出来、无「加载失败」；并发下瞬时超时才显示同一行字 | 对 tree/ 目录也用「加载失败」判失效 |
| 「加载失败」只对 blob/（文件视图）是可靠软 404 | 落地 `/blob/` 说明 gitcode 认定这是叶子路径、加载失败即 404；留在 `/tree/` 说明目录存在、只是列表没刷出来 | — |

判据落成两条：① 只认落地 `blob/`（`is_repo_file()`），`tree/` 目录的「加载失败」忽略；② 命中后再
刷新重试一次，内容出来了算瞬时失败（通过），仍失败才是软 404（A1）。改完后 A1 误报从 7 清零。

## 递归爬取（2026-09-08）

从「固定 19 页、一层深度」改成**递归 BFS**：用户要 CANN 板块里链到的所有站内页面都爬一遍、
所有地址汇总成一张表。范围与判据：

| 事实 | 数据 | 否掉了什么 |
| --- | --- | --- |
| 只递归 `/cann/` 前缀的站内页 | `CRAWL_PREFIX = "/cann/"`、`MAX_PAGES = 500` 兜底；外链、站内非 `/cann/`（文档库/论坛/公告动态）、静态文件（`SKIP_EXT`）都是叶子节点——探测可达性但不递归 | 按 URL 全站深爬（子页签不是链接、不改 URL，早先已否掉） |
| 两阶段：先入口页算 chrome，再 BFS 正文链接 | 阶段 A 爬 21 个入口页取 href 交集 = 页头页脚；阶段 B 从正文链接 BFS，`canonicalize` 去重（host 小写/#fragment/尾斜杠/丢 query） | 固定页面清单、只扫一层 |
| 外壳塌陷判据只作用于入口页 | 递归子页链接数天然少，按 45 条判会误判塌陷；深页以「正文渲染出」为准 | 把 `SHELL_LINK_MAX` 套到深页面 |
| 实际递归深度为 0 | 本轮 21 个入口页就是全部 `/cann/` 页，正文链出去的多是文档库/论坛/代码仓等非 `/cann/` 页，按规则不递归，`层级` 全为 0 | 以为 `/cann/` 下还有子页 |

日志里 `S3 站内/cann 31` 是**未去重的原始地址数**——同一页的尾斜杠、子页签 query 变体
（如 `open-map?name=h0205`）各算一条；`canonicalize` 归一后就是 21 页。

新增「全部地址」表（`last-run.json` 的 `全部地址` + `addresses.csv`）：每条含 序号/层级/所在页/
锚文本/类型/判定，按「页面顺序（爬取顺序）→ URL」排序，不是 URL 字母序。入口页也从 19 扩到 21，
多了两个只存在于 sitemap、不被任何页链接的孤儿页「治理架构/社区章程」。

## 改动纪律

**改判据必须重跑真实站点，看假阳性数**，不许只看退出码。三轮迭代里每一轮退出码
都是 1，但假阳性从 2 降到 0——退出码证明不了判据对。

`A4` 是唯一未验证负例的规则：正例（token 能对上）验证了五条，
但「链接可达而名实不符」的真实样本至今没出现过，假阳性率未知。
在真实负例出现前，A4 的每条命中都要人工核对。

2026-08-29 连跑三轮，A4 假阳性复现 1 次：CSR 公告页只渲染出外壳标题
`产品公告-昇腾社区`，正文没出来，版本号 token 自然找不到，三条版本公告全部误报。
`settle()` 的稳定判据分不开「外壳恰好稳定」与「渲染完成」——这正是上表
「渲染未完成时真假页正文完全一样」那一条，至今没有解法。
