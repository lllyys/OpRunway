# CANN 页面巡检

替代人工每天打开 `hiascend.com/cann` 逐个点链接的动作。取链、探测、判定、出报告全自动，
网页内容不进上下文，你只读结论。

覆盖顶部导航全部 21 个入口页，并递归爬取 `/cann/` 下链到的所有站内页，把发现的地址汇总进 `addresses.csv`。算子库、通信库、领域加速库、开源项目列表这几页的子页签
**不是 `<a>`、点击不改 URL**，脚本会逐个点开再取链——不点就漏掉那一页的大部分内容。

## 入口参数

| 参数 | 含义 | 取值约束 | 初值推断 |
| --- | --- | --- | --- |
| `输出目录` | 报告与状态的落点 | 已存在或可创建的目录 | 用户没给就问，不要默认写进仓库 |

## 前置检查

`page_inspect.py` 的 S1 阶段自己做这件事：检查 `httpx`、`playwright` 可导入，
本机 Chrome 可启动，21 个入口页全部可达。任一不满足它直接以退出码 2 停下并打印缺什么，
**不出半份报告**。你不需要提前自己检查一遍。

依赖缺失时装：`pip install httpx playwright`。**不要跑 `playwright install`**——
脚本用 `channel="chrome"` 复用本机 Google Chrome，不需要下载 chromium。

## 主流程

两条命令，先判定后渲染。分开是为了判定与渲染不会给出两个不一致的结论：

```bash
python3 scripts/page_inspect.py --out <输出目录>
python3 scripts/render.py --out <输出目录>
```

第一条的退出码就是结论：

| 退出码 | 含义 | 你要做什么 |
| --- | --- | --- |
| `0` | 全部正常 | 照样渲染报告，告诉用户今天没问题 |
| `1` | 有命中 | 渲染报告，把命中的规则和条数报给用户 |
| `2` | 阻塞 | 报告不可信，不要渲染。按 `references/troubleshooting.md` 处置 |

产物：

```text
<输出目录>/cann-page-inspect/
├── report.html          给人看的唯一产出，双击打开。顶部「检查域」给出
│                        本轮扫到的页签数、链接数、内容块数，并逐页列出
├── addresses.csv        递归爬取到的全部地址清单（UTF-8，Excel 直接打开筛选）
└── .state/
    ├── baseline.json    每条异常的首次发现日期，报告据此标「今日新增 / 已连续 N 天」
    ├── last-run.json    本次全量结果，有人质疑结论时拿它对账
    └── run.log          运行日志，只在退出码 2 时看
```

## 七条规则，两组

报告和 `last-run.json` 都按这两组组织。用户问「这条为什么算错」时照这张表回答：

**A 组 · 链接可用性**——点了之后能不能拿到东西：

| 编号 | 检查项 | 判定依据 |
| --- | --- | --- |
| A1 | 链接打不开 | 三次重试全部失败：DNS / 连接 / 超时 / 4xx / 5xx；或代码仓（gitcode/gitee）文件视图 `blob/` 显示「加载失败，请刷新重试」= 文件不存在的软 404 |
| A2 | 打开是「页面不存在」 | HTTP 返回 200，但渲染后正文是站点的失效页 |
| A3 | 被弹到登录页或首页 | 终点 URL 落在登录页、站点首页或根路径，没停在原目标 |
| A4 | 落地页与链接说的对不上 | 锚文本或 URL 的关键 token 未出现在目标页标题或正文 |

**B 组 · 内容时效与一致性**——拿到的东西是不是过期或自相矛盾：

| 编号 | 检查项 | 判定依据 |
| --- | --- | --- |
| B1 | 下载版本与公告不一致 | 下载页版本号未出现在主页任一条版本公告的锚文本里 |
| B2 | 会议已结束仍在展示 | 会议链接 URL 内的日期早于巡检日 |
| B3 | 内容长期未更新 | 最新版本公告距今 > 90 天，或最新动态新闻距今 > 30 天 |

`mailto:` / `tel:` / `javascript:` / 纯锚点不进判定——httpx 对它们报 `UnsupportedProtocol`，
会被 A1 判成链接失效。它们在报告的检查域表里单列「不可探测」一列，不是当没看见。

**A4 的假阳性风险最高。** 它靠 token 匹配判「名实相符」，正例已验证，
但可达却名实不符的负例尚未在真实页面上出现过，假阳性率未知。
A4 命中时先自己打开目标页看一眼，再报给用户。

**阈值都在脚本顶部的常量区**，B3 的 90/30 天、A1 的重试次数、限流状态码都在那里，
改一行即可，不要改判定逻辑。

**编号在 2026-08-29 从 R1–R7 改成 A1–A4 / B1–B3。** `render.py` 里的
`RULE_ID_MIGRATION` 负责把老 `baseline.json` 的键迁过来，历史「已连续 N 天」不会断。

## 报告的口头汇报

报告本身按两组规则组织，你转述时**只说命中的**，不要复述七条规则。每条给三样：
哪个页签的哪个位置、实测到什么、目标链接。正常的链接一条都不要提。

用户问「一共扫了多少」时，报告顶部的「检查域」和它下面的逐页表直接给数，
不要口算或估。

全部正常时就一句话，不要为了显得干了活而罗列检查过程。
