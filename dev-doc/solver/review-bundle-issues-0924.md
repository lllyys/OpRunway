# solver-review-bundle-cholesky 问题清单

> 依据：0923 两份 Cholesky 任务书（实数 Spotrf 族、复数 Cpotrf 族）2026-09-24 重构后的 §3.2 精度要求，
> 对照 `solver-review-bundle-cholesky`（criteria 内核 s1-A2 / renderer s1-D1）。
> 判定内核工程质量良好（fail-closed、76 项测试、formal 恒 PENDING_RULING），残差实现
> （DPOT01/02/03 升精度度量、半三角 DLANSY 范数、Hermitian 共轭镜像、对角虚部校验）与
> percision_standard 工程口径一致，无计算错误。以下问题均为**契约层**（阈值式、判定支路、
> 用例覆盖）与新版任务书的脱节。

## A 档：与新任务书直接冲突（必须改）

### A0 Batch 类算子的抽样验证方法（节约验证时间）

Batch 用例的矩阵数 = batchSize × case 数，全量逐矩阵验证的残差计算开销大
（batchSize 上限 3000）。为提升验收效率，batch 类算子的精度验证按以下方法执行：

- **构造**：控制随机数种子，每个用例只生成 **5 个内容不同的矩阵**；这 5 个矩阵
  在 batch 轴上的摆放位置由随机数种子决定（随机摆放），其余 batch 槽位由这
  5 个矩阵按种子规则重复填充。
- **精度验证**：只对比 **5 个内容不同的矩阵**（每种各取 1 个）——按 3.2.2 的
  同式残差 + 同阈值逐矩阵判定，任一矩阵超阈值则该用例不通过。
- **其余矩阵的一致性验证**：剩余 batch 槽位的矩阵与被抽样的 5 个矩阵之一
  **内容相同**，其输出结果（分解因子/解/逆）必须与同内容矩阵的输出
  **二进制一致（bit-wise）**——相同输入在同一实现下多次执行本就要求
  bit-wise 一致（任务书确定性条款），不同槽位的同内容矩阵输出不一致
  即为求解错误。该项逐槽位核对，无残差计算开销。
- 抽样矩阵与槽位映射关系（种子 → 摆放 → 槽位 ↔ 内容索引）由用例包固化并
  随包发布，验收方与开发者用同一份 index，杜绝「映射解释不一致」。

判定口径：精度判定只作用于 5 个内容不同的矩阵；一致性核对不产生残差，
仅要求 bit-wise 相等。ratio_cpu_mean 按用例集级常数随包固化（内容不同的
矩阵只有 5 个，见 A2）。

### A1 potrf / potrs 阈值式过时

- bundle 现状（`criteria/thresholds.py`）：
  - potrf：`min(30, max(10·ratio_cpu, 1))`（收紧式，地板 1，上限 30）
  - potrs：`max(2·ratio_cpu, 30)`（上浮式，地板 30）
- 新任务书定稿：
  - potrf / potrs 统一为 `max( 5·ratio_cpu, 3·ratio_cpu_mean )`
  - 相对线系数统一 5×：以「合法实现相对 CPU 参考的实测最大劣化」为标定基准，
    覆盖散布并留健康余量；原 30 地板在现行用例域只起放松作用、无防塌缩价值，
    由 mean 线承担「残差落底噪区时托住阈值」的职责。
- 影响：全部 fallback 判定结果与任务书不一致。

### A2 ratio_cpu_mean 概念缺失

- bundle 只有逐 case 的 ratio_cpu（index.json 随包发布），无均值统计。
- 新任务书：potrf/potrs 阈值第二支 = `3·ratio_cpu_mean`，定义为
  「本算子测试用例集全部 case 的 ratio_cpu 算术平均」；
  Batched 用例取**当前 case 内 batch 个矩阵各自 ratio_cpu 的算术平均**
  （仅在本 case 内统计，不跨 case 汇总）。
- 处理意见（**统一为发布前预计算、全部固化随包**）：
  - ratio_cpu_mean 是用例集级常数，无论 batch 与否都在**用例包发布前算好**：
    用 CPU FP32/COMPLEX64 参考链路把用例集内**所有内容不同的矩阵**各跑一遍
    得到 ratio_cpu，求算术平均后作为固定值写入用例包（index.json 随包发布，
    随用例集版本更新）；验收时不实时计算，直接读包；
  - batch 用例中「内容不同的矩阵」= 抽样验证的 5 个矩阵（A0 主路径，
    其余槽位是这 5 个的重复，残差相同不重复计算）；
  - 实现要点：index.json schema 增加用例集级 ratio_cpu_mean 字段（非 batch
    与抽样 batch 用例共用），全部随包固化，无实时计算路径。

### A3 potri 阈值错误

- bundle 现状：复用 potrf 收紧式 `min(30, max(10·ratio_cpu, 1))`（地板 1）。
- 新任务书定稿：`max( 5·ratio_cpu, 0.1 )`。
- 修订依据（通用性说明，不针对特定实现）：
  - 相对线系数与 potrf/potrs 统一为 5×——求逆的合法实现间散布实测不超过 5×，
    更大的系数只起放松作用；
  - 绝对线取 0.1 而非 1：DPOT03 分母含 n·‖A‖₁·‖C‖₁ 双归一（逆的幅值随 ‖A‖₁
    增大而缩小），合法实现的残差被压在远低于 1 的量级，地板 1 失去判别意义；
    0.1 为「合法实现散布上界 × 健康余量」的标定结果；
  - mean 线（3·ratio_cpu_mean）在 potri 上结构性不适用：CPU 残差均值比实现间
    散布上界低一个数量级（归一化过强所致），任何 K2 系数都无法同时满足
    「托住散布上界」与「保持健康余量」，故第二支用常数。
- 验证方式：以合法参考实现的逐 case 残差对阈值扫描，要求全 case 通过且
  最薄余量 ≥3×（0.1 地板下满足）。

### A4 ε 口径差 2 倍

- bundle：EPS32 = 2^-24（unit roundoff）。
- 任务书 3.2.2：写的是 2^-23（machine epsilon）。
- 影响：ratio 以 ulp 计数，ε 差 2 倍 = 全部阈值差 2 倍。
- 处置建议：**任务书统一改为 2^-24**——ratio 的定义是"残差折合多少个最低位"，
  归一基准应取 unit roundoff（一个最低位舍入的最大相对误差）；LAPACK 判据例程
  的 DLAMCH('E') 亦为此口径；全部既有定标数据基于 2^-24。

### A5 potrf 第一层主判目标相反

- bundle 现状：主判 = 还原 recon（L·Lᵀ / Uᵀ·U 取指定三角）vs A64；
  F vs golden F 直审降为诊断项（并报不主判）。
- 新任务书 3.2.1 条 6：与 golden **直接逐元素对比**为主判
  （Hermitian/对称正定下因子数学唯一），3.2.2 残差复核为不通过时的第二步。
- 二者数值上等价（重构残差健康 ⟺ 因子正确），但层次归属相反。须任务方裁决：
  ① 按新任务书：golden 直审主判，recon 移入 3.2.2 复核层；
  ② 或承认 bundle 口径更优（recon 主判对高幅值 case 更稳健），反向修订任务书定稿句。

## B 档：bundle 功能缺失（任务书有要求、bundle 未实现）

### B1 正定用例的正定性保证

- 精度判定用的正定矩阵，在**用例构造环节保证正定**即可——构造算法本身
  确保 SPD（对角占优或 A = BᵀB + n·I，数学上无例外地正定），
  不需要运行时正定性检查。
- 例外：故意构造的非正定用例（见 B2/B3）不在此列，构造时即打破正定性。

### B2 info 契约判定支路缺失（非 batch 算子）

- judge 入口第一道门：`info != 0 → error FAIL`（verdict.py），被测 info=k>0
  走「不可裁」分支，无「核对 k 是否正确」的判定路径。
- 三份 sample report 均自述：`info 契约/spotrf —— 证据不足……本片模拟被测，
  未执行该场景`。
- 处理意见：
  - **用例侧**：选取 3 个中等规模用例，除正常正定用例外，各额外构造 1 个
    非正定用例用于功能测试——对构造的 SPD 矩阵将第 k_min 阶顺序主子式变为
    不正定（如对角减大数），使「最小不正定顺序主子式阶数」构造时即已知；
    S/C 两种精度、实/复两族均覆盖；k_expected 连同矩阵一起入包；
  - **判定方式**：非正定用例只做 **info 输出对比**（info = k_expected 判
    PASS，否则 FAIL），不做残差精度判定（非正定输入下分解中途失败，
    残差无意义）；
  - **ratio_cpu_mean 口径**：计算用例集级 ratio_cpu_mean 时**只统计正定用例**
    的 ratio_cpu，非正定用例（info 对比专用）不计入——两类用例分列，
    index.json 中标记用途（精度判定 / info 契约检查）；
  - **判定内核**：新增 info 契约检查支路——
    - potrf：被测 info = k_expected 判 PASS，否则 FAIL；
    - potri：构造奇异因子（某阶顺序主子式为零），info = k_expected 判 PASS；
    - potrs：本无正值分支，构造用例仅验证非法参数路径（info = -i），
      不涉及 k。
  - 该支路与精度判定相互独立（info 正确性检查不依赖残差），按 C4 的既定口径
    作为独立检查项实现。

### B3 info 契约判定支路缺失（batch 算子）

- Batched 判定整体缺位（README_review 问题 6 自述「证据不足、族级不判通过」）：
  新任务书已给出完整口径——逐矩阵按同式计算 ratio 并逐矩阵判定，任一矩阵
  超阈值则该用例不通过；抽样验证方法见 A0。
- 处理意见：
  - **用例侧**：选取 1 个中等规模 case，将其中 1~2 个矩阵构造为非正定
    （其余矩阵保持正定），各矩阵的 k_expected（正定矩阵为 0）入包，
    用于验证 infoArray 逐矩阵独立写入；
  - **判定方式**：非正定矩阵按 B2 同款只做 info 输出对比，不进残差判定；
    batched 逐矩阵核对 infoArray[i] 与各矩阵的 k_expected
    （参数错写 infoArray[0] = -i、potrsBatched 标量 info 仅报参数错，
    一并覆盖）；
  - **ratio_cpu_mean 口径**：同 B2，非正定矩阵不计入 case 内均值。

### B4 确定性检查缺位

- 「合法用例重复执行 bit-wise 一致」只有证据不足占位（sample report），
  无复跑驱动与比对实现。
- 处理意见：同一输入重复执行多次（如 ≥5 次），输出（含 info）之间
  bit-wise 一致即通过——结果两两比对，无任何不确定性问题。

## C 档：任务书自身待裁矛盾（bundle 8 问中真正悬空的）

### C1 Q2：混合容差双套数值矛盾

- 任务书表：rtol=2^-10 / atol=2^-16；opbase 最新混合容差标准：FP32 均 2^-13。
- bundle 靠 T3 flag 双轨并行（任务书套主判、标准套对照），但正式验收必须裁一个。
- 处置建议：任务书引用的标准 URL 是旧版，若以 opbase 最新版为准须改任务书表；
  若任务书表为准，回复验收方明确 T3 按任务书套收束。

### C2 Q3："1e-2 or 32·ULP" 的 or 语义

- 问题：两种解释都不可用——
  - 按 32·ULP（≈1.9e-6）：矩阵级还原误差随 n·‖A‖·ε 自然增长，合法实现也必然
    超限 → 第二层对任何实现都不独立通过，条款失效；
  - 按 1e-2：对矩阵级误差几乎不设限，条款形同虚设。
- 根因：该门的两种候选语义（逐元素 ulp 上限 / 矩阵级绝对上限）作用于不同的
  误差对象，or 连接使条款在两个解释间无法自洽。
- 处置建议：**删掉 or，max_abs_error_limit 定为 1e-2**——逐元素精度约束由
  rtol/atol 承担，矩阵级精度由残差复核层承担，本门只作粗筛；
  ULP 参照值随 ε 口径（A4）统一。
- 验证方式：以合法参考实现的 layer1 统计验证新上限下第二层可独立通过
  （matched_ratio ≥ 0.99 且 max_abs ≤ 上限），而非全部流入第三层。

### C3 Q5：复数拆实/虚口径

- bundle 实现：实部、虚部各自计算 matched_ratio 与 max_abs，双侧同时达标
  （不合并成 2N 元素互相稀释）——与复数任务书 §3.2 第 3 条本意一致。
- 待任务方书面确认（bundle 恒记 T7 flag）。

### C4 Q7：info / 确定性独立于精度判定

- bundle 按「独立检查项」处理，不并入精度判定流转——合理，确认即可。

## 建议处置顺序

1. **任务书侧（我们自己改）**：C2（删 or 定 1e-2）、A4（ε 统一 2^-24）；
2. **裁决 A5**：第一层主判用 golden 直审（合任务书）还是 recon（合 bundle）；
3. **阈值修订包回复验收方**：A1/A2/A3 + cholesky_precision README 定标依据；
4. **bundle 待办**：B1（正定性保证）/B2（非 batch info 契约）/B3（batch info
   契约与 Batched 判定）优先级最高——功能性验收项；
   B4（确定性检查）随 NPU 交付节奏补。
