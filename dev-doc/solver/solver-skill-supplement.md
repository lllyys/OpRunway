### 2026-09-23 · 任务包模式、精度标准与数据构造规则（七点）

原话要点（编号沿用 Mr.0 原文）：

1. solver 的任务包（case 与脚本）由我们提供：先写 case-gen，产物先给开发者自测；
   验收 = accept skill + case-gen 产物 + 开发者算子。
2. 精度验收用最新标准：
   `https://gitcode.com/cann/opbase/blob/master/docs/zh/ops_precision_standard/mixed_tolerance_standard.md`。
3. 各算子的输入有合法性要求，只有满足要求的才是合法输入；0923 目录的 cu 脚本记录了
   GPU 侧如何构造合法输入，skill 要把这套规则与方式转换过来。
4. `cases.json` 是测试用例描述文件，用来构建精度与性能测试用例。
5. case-gen 功能之一：读 cases.json 与 cu 文件，参考 cu 的数据构造逻辑生成一个
   python 脚本；任务发布者把脚本给开发者用以构造实际数据，同时也用这个脚本生成
   一份测试用例数据给到开发者。
6. 测试用例数据两用：性能测试与精度测试，两者输入值相同。
7. 性能测试从 bench_result.json 读对应时长、与实测比较；精度测试与 numpy 或 scipy
   的 CPU 计算结果比对。

影响到的既有结论：

- **精度标准张力落定一半**：不采 solver_tasks-main 的三层制（那是建议稿），采 opbase
  最新混合容差标准；solver_tasks-main 降级为输入构造与踩坑参考。标准原文待拉取，
  阈值与「解不唯一算子比什么」以原文为准。
- **任务包升级为对外交付物**：消费者从 accept 一家变成开发者自测 + 任务发布者 +
  验收者三方，case-gen 产物成熟度门槛高于乙估算时的内部件口径——成本复核点。
- **角色模型补充**：case-gen 的直接用户是任务发布者（发脚本与数据给开发者），
  不是验收者的内部工序。
- **bench.cu 身份升级**：从「参考耗时产地 + 结构反面教材」升为「合法输入构造规则的
  权威来源」；case-gen 要做的是把 cu 构造逻辑转写成带显式 seed、可落盘的 python
  生成器（cu 自身 rand() 无播种、序列依赖清单顺序，不能照搬只能转写）。
- **case-gen 是「生成器的生成器」**：产物含一个 python 数据构造脚本 + 一份数据集，
  与 BLAS 线 harness-gen 的形态同构。

待 Mr.0 裁定或向任务方澄清的张力：

- 第 7 点「从 bench_result.json 读时长比较」与硬边界 10「仅有 min/max/avg 只能停在
  摸底态」及任务书「T_A100 开发者实测、预热≥10/采样30/中位数」相撞——bench_result
  是竞品 avg 口径。按第 7 点执行则硬边界 10 需改写，待明示。
- 第 6 点「性能精度同输入」：任务书 P-xx 的性能规格（大 batch）与精度覆盖（九类场景）
  的用例集合不天然重合，「同输入」是按交集执行、还是性能 case 全部附带精度校验，待确认。

标准原文解读（2026-09-23 拉取，存 `repos/opbase-precision-standard/`；
旧 `experimental_standard.md` 已 404，本标准是其后继）：

- **FP32 阈值：rtol = atol = 2⁻¹³，matched_ratio 0.99，max_abs 1e-2 or 32·ULP**。
  与任务书的 rtol 2⁻¹⁰ / atol 2⁻¹⁶ 不一致——第三处待澄清张力：任务书容差与最新
  标准表谁生效。「or」的取向标准原文同样未定义。
- **单标杆比对**：与更高精度实现（CPU 或昇腾小算子拼接）直接比——与第 7 点的
  numpy/scipy golden 吻合。
- **标准只定「怎么比」（逐元素混合容差），不处理解不唯一**；比什么（还原产物、
  指定三角、解向量）仍由任务书定。solver_tasks-main 对旧标准的批判（解不唯一时
  逐元素对比在契约层不成立）对新标准同样成立，所以「先还原、再按标准比」的组合
  仍是必需，不因换标准而失效。
- **§1 用例生成规则是 case-gen 覆盖设计的直接依据**：50/50 均匀/正态与
  solver_tasks-main 的造数规约同源；维度取 2 的幂与 2 的幂减一（n=31 的来历）；
  特殊场景表（空 tensor、标量、边界、INF/NAN）与「全组合覆盖」口径。
