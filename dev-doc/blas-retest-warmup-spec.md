# blas-accept 性能复测与 warmup 行为规格（spec v6，2026-09-17）

本文是行为契约：定义复测与 warmup 之后系统「是什么」，不含实施顺序与文件改动清单
（那是 plan 的事）。修订史：v2 并入 Codex 闭环与冷读评审及 G1 spike（门控项，
定义见 §10）；v3 按用户裁定放宽校验（§1）；v4 闭合四个边界；v5 补预热失败去向与
换卡推导；v6 按终轮冷读补 WAIVED 代表轮规则与术语锚定。定稿后内容折入
`perf-protocol.md`（下称 P）与 `run-chain.md`（下称 R），本文转历史记录。

## 1. 范围与用户裁定

只改性能侧：性能量具（A4 阶段运行的 `verify_performance.py`，见 R「A4 性能」）与
accept 的 A5 性能段。精度量具、精度侧 `-rerun`（精度复跑 run-id 后缀，只归因、不改判，
见 R「复跑与归因」）与首轮闭合要求（首轮 JSON 的 cases 集合必须与性能期望集完全相等）
保持不变。isolated-acceptance 无头通路（正式验收用的无头编排 skill，主机侧）不在
范围内。

对现行契约的三处显式变更（除此之外，默认参数下首轮行为不变）：

- 首轮性能 JSON **加法扩展**两个字段（§4.4），解决复测绑定无锚点的问题。
- 现行「重复 run-id 时覆盖写错误 JSON」的行为废除（§3）。
- 首轮允许显式传 `--warmup`（§7）；开启时首轮 JSON 逐例加法出现 `warmup_exit`、
  顶层出现 `warmup`，默认 N=0 时这两处不变。

用户裁定（2026-09-17，Mr.0）：

- pass-once：一个 case 在任一有效轮次 PASS，即为 PASS；该 PASS 证据永久保留，
  未处于豁免态时它决定有效状态（「有效轮」见 §2 与 §5，「豁免态」的计算见 §6）。
- 复测支持多轮；跑哪些 case 由用户点名（一般是失败例，不做机械限制）。
- 复测可指定不同物理卡（**当前 v1 未开放**，见 §10 G1；默认沿用首轮的卡）。
- 「跳过」= 豁免：该 case 退出裁决分母。
- A5 重跑覆盖旧报告；证据 JSON 不可变，报告是当前投影。
- 默认 warmup 是否开启由真机实验与 GPU 基线口径共同决定（§10 G2）。
- **校验宽松化**：信任模型是无主观恶意——校验只为捕捉无意错误（跑错工程、换错基线、
  旧产物混入、工具缺陷），不做防篡改机械。问题轮次跳过并醒目告警，不让整体裁决翻车。

## 2. 术语

沿用现行文档的术语在此只给定位：**accept**、**量具**与 **harness** 见 R「输入与目录」；
**A1–A5** 是验收五阶段（R 各节，A2′ 见 R「A2′ 三文件」）；**性能期望集**见
P「适用范围」（本文「可比期望集」是它的同义词，指能配到非空 `gpu_ms` 基线的
`TC_PF_` 用例集）。逐例状态分头定位：`CRASH`（执行成功证据缺失或不合格，不断言
进程崩溃）与 `NO_KERNEL` 见 P「执行成功证据与逐次判定」，`PASS/FAIL` 判据与
`NO_REF` 见 P「统计与比对」，`MISSING` 见 R「A3 精度」（未出现在列举或结果中），
`TIMEOUT` 是进程超时终态。`device_resolved` 见 R「A1 环境」的设备选择；`ratio`、
阈值 0.8 见 P「统计与比对」；`manifest.json` 与 `check.json` 见 R「A2 有无门」；
**产物目录**（A5 三类产物的位置，非工作目录）见 R「A5 结论」；**A3 机**是一台
实测机器的别名（见 P「op_summary 解析」），与 A3 精度阶段同名不同物。

命名约定：本文说的 **v1** 指「换卡附录（§11）未启用」的当前功能形态，是功能版本
记号，与 `schema_version`、`fold_protocol_version` 两个数值字段无关。

本文新造术语：

| 术语 | 定义 |
| --- | --- |
| 首轮 | 既有 A4 产出的 `performance_<id>.json`；`<id>` 即 base run-id |
| base run-id | 首轮的 run-id，复测轮借 `base_run_id` 字段回指它，两者严格同义 |
| 复测轮 | 绑定同一 base run-id 的一次后续声明，编号 1..N，分测量轮与豁免轮 |
| 测量轮 | 由性能量具执行、对点名 case 重新采集并出结果的复测轮 |
| 豁免轮 | 由 accept 写出的声明记录，宣布若干 case 退出裁决分母，不做任何采集 |
| 完成轮 | 结果 JSON 存在于约定路径且可解析的复测轮 |
| 阶段目录 | 一轮运行的独占产物目录 `runtime/results/<run_id>/performance/`；复测轮的 run_id 即 `<id>-retest-<k>`，目录名里的 k 就是轮号 |
| 中断轮 | 阶段目录存在而结果 JSON 缺失的复测轮；占用轮号，不参与折叠 |
| 有效轮 / 无效轮 | 完成轮过/不过 §5 检查为有效/无效；结果文件存在但不可解析的轮也是无效轮。无效轮占用轮号、跳过折叠、报告醒目列出 |
| 折叠 | A5 把首轮与全部有效轮合并为逐例有效状态的机械规则（§6） |
| 有效状态 | 折叠后每个 case 的最终状态，报告与总结论只认它 |
| 代表记录 | 有效状态对应的那一轮的逐例记录，报告主表展示它的数值 |
| pass-once | 折叠规则：测量历史中存在 PASS，未豁免时有效状态即 PASS |
| warmup | 采集前的裸 gtest 预热进程（§7）；与 harness 内部预热、msprof 内部行为无关 |

## 3. 证据保护契约（先决，独立于复测；只约束性能量具与 A5）

对象分三类，规则不同：

- **原始证据**：首轮与复测轮的结果 JSON、各阶段目录内的采集产物。一经写出不可变；
  量具对已存在的结果 JSON 路径一律不写——`--run-id` 对应结果 JSON 已存在时直接拒绝
  退出（`RUN_ID_EXISTS`），不向该路径写任何内容。现行「环境失败 JSON 原子覆盖同名
  文件」的行为废除。
- **派生裁决**：`verdict.json` 与报告。可随每次 A5 重跑覆盖（§8），因为它记录了输入
  清单与规则版本，随时可由原始证据重演。
- **归档副本**：`intermediate/` 下的复制件。每次 A5 在临时目录整体生成后替换，
  不留 stale 文件。

失败落盘按三类区分：

1. **单例终态**：逐例 CRASH/TIMEOUT/MISSING/NO_KERNEL 是正常记录，量具继续处理
   其余 case，最终写出完整结果 JSON——首轮照常出首轮 JSON，复测轮成为完成轮。
2. **环境失败（首轮，不涉及轮次术语）**：现行退出 3 的人工处置流程保留
   （R「A4 性能」：删目录与 JSON 后同 id 重跑一次）——那是**人工授权的显式删除**，
   不是量具覆盖，且只适用于首轮。
3. **量具异常终止与复测轮环境失败**：不写结果 JSON，阶段目录与日志留存，复测轮
   因此成为中断轮。复测轮不删目录重用轮号，失败就弃号换下一号。错误原因从日志与
   stderr 读取。

复测轮不接受 `--out` 自定义结果路径：结果一律落
`runtime/results/performance_<id>-retest-<k>.json`。

## 4. 复测轮记录（schema v1）

文件名 `performance_<id>-retest-<k>.json`，k 为轮号。轮序以**文件名的 k** 为准；
JSON 内 `round` 与 k 不一致时记 warning，按文件名裁。

### 4.1 共有字段（两种 kind 都必填）

`schema_version`（整数，本版为 1）、`base_run_id`、`round`（整数）、
`kind`（`"measure"` 或 `"waive"`）、`op`/`family`/`soc`/`repo`（身份字段，含义与
推断规则见 R「A2 有无门」）、`started`/`finished`（该轮进程开始与结果写出前的时刻，
ISO 格式）。

### 4.2 测量轮专有字段

- 点名与执行：`requested_cases`（用户点名清单，非空、无重复、每项 ∈ 性能期望集）、
  `cases[]`（逐例记录：身份字段 `name` 为用例名，其余记录字段与首轮相同——清单见
  P「结果与退出码」的逐例字段段——另加 `warmup_exit`，语义见 §7）。量具保证每个
  点名 case 在 `cases[]` **恰好一条**记录（跑不出的用 MISSING 占位，不缺不多不重复），
  未知点名在起跑前报参数错误。测量轮逐例状态的合法集合是
  `PASS/FAIL/NO_KERNEL/CRASH/TIMEOUT/MISSING`——复测集全在可比期望集内，
  `NO_REF` 出现即属工具缺陷。
- 预热：`warmup`（本轮 N 值，整数 ≥0，语义见 §7）。
- 设备：`device_requested`（本轮请求值；不接受 `auto`）、`device_resolved`
  （实际物理卡）。v1 规则的比较基准是首轮 JSON 的既有字段：首轮 `device`
  （原请求）为显式卡号时，本轮两个字段都必须等于它；首轮 `device` 为 `auto` 时，
  本轮两个字段必须等于首轮的 `device_resolved`（auto 证据字段，见 R「A1 环境」），
  量具按首轮 auto 的同一机制执行（该物理卡经 `ASCEND_RT_VISIBLE_DEVICES` 映射为
  逻辑 0）。跨卡复测见 §11 附录，未启用。
- 绑定（跨轮不变量，必须与首轮 JSON 的对应字段一致）：`binary_sha256`、`csv_sha256`
  （二进制与部署 CSV 的证据哈希，见 R「A3 精度」的证据字段）、
  `normalized_baseline_sha256`（运行时包规范化基线的哈希，基线见 R「A2 有无门」）、
  `threshold`、`calls_per_case`（计数口径见 R「A2′ 三文件」）、`verifier_sha256`
  （量具脚本自身的 SHA-256）。
- `argv`：本轮量具进程的完整命令行参数（字符串数组，含脚本名），测量轮必填；
  仅存证参考，不作任何机械判定输入。

逐例字段一致性：状态为 PASS/FAIL 的记录必须有数值 `ratio` 与 `kernel_us`，
证据缺口状态必须无 `ratio`。

### 4.3 豁免轮专有字段

`waivers[]`，每项 `{case, reason}`：case ∈ 性能期望集且轮内无重复，reason 逐 case
必填非空。豁免轮由 accept 写出，不含设备、绑定、requested_cases 字段，
也不做任何设备探测或采集。

### 4.4 首轮绑定扩展（对现行首轮 schema 的加法变更）

新版量具渲染出的 `verify_performance.py` 在首轮 JSON 顶层同样写出
`normalized_baseline_sha256` 与 `verifier_sha256`（`threshold`、`calls_per_case`、
`binary_sha256`、`csv_sha256` 现行已有）。复测轮的绑定校验以**首轮 JSON 里的值**为锚，
不以当前 manifest 为锚——manifest 会被重跑 A2 改写，不能替历史背书。
首轮 JSON 缺这两个字段即判定该工作目录不支持复测（§9）。

## 5. 轮次有效性

候选轮按文件名模式 `performance_<id>-retest-<k>.json` 发现。文件不可解析 → 直接归
无效轮（占号、告警、跳过）。可解析的完成轮再做下表检查，**任一不过 → 该轮为无效轮：
跳过折叠，报告醒目列出轮号与原因，并明说「该轮未生效」；其余轮照常折叠，整体裁决
不因此翻车。** 这与首轮不同——首轮无效仍按现行规则处理（如缺失或 exit 3 → 证据不足）。

| 检查 | 适用 kind | 判据 |
| --- | --- | --- |
| 结构 | 两者 | `schema_version` 认识、§4 该 kind 必填字段齐全、逐例字段一致、逐例状态在合法集合内 |
| 身份 | 两者 | `base_run_id` 与本次 run-id 相同；op/family/soc/repo 与首轮一致 |
| 绑定 | measure | §4.2 绑定字段与首轮 JSON 锚值一致（不一致说明测的不是同一对象，数值不可比） |
| 设备 | measure | `device_requested`/`device_resolved` 符合 §4.2 的 v1 规则 |
| 点名 | measure | `requested_cases` 合规，且每个点名 case 在 `cases[]` 恰好一条记录 |
| 豁免 | waive | `waivers[]` 合规（§4.3） |

轮号占用与顺序：完成轮与中断轮都占号；下一轮号 = 已占用轮号最大值 +1。轮号出现
空缺只记 warning，不影响折叠。复测轮期望一次跑一个（串行是使用约定，不是机械校验）。

信任模型：以上检查针对无意错误——跑错工程、换错基线、旧产物混入、工具缺陷。
本规格不提供防篡改保证，也不为此增加机制。

## 6. 折叠

折叠只在 accept（A5）一处实现，量具不读任何历史 JSON。折叠对象 = 首轮 + 全部
有效轮（§5）。逐例计算两个独立量：

1. **豁免态**：取涉及该 case 的最后一个声明（按轮号序）——豁免轮列入即豁免；
   更晚的有效测量轮再测该 case 即撤销豁免。首轮记录、中断轮与无效轮都不是声明。
2. **测量历史**：首轮记录加全部有效测量轮中该 case 的记录，按轮序排列（首轮视为
   第 0 位）。每条记录永久保留。

有效状态判定顺序：

1. 豁免态成立 → `WAIVED`。不进分母。**代表记录 = 使豁免态成立的那个豁免轮**
   （数值栏留空，展示豁免理由）；另以该例最近一次测量记录（若有）作参考值标注，
   参考轮与代表轮是两个独立字段，不混用。
2. 测量历史中存在 PASS → `PASS`，代表记录取**最早** PASS 的那轮。
3. 无 PASS 但存在可比测量（FAIL）→ `FAIL`，代表记录取 ratio 最大的那轮，
   同 ratio 取轮号小者。
4. 只有证据缺口（NO_KERNEL/CRASH/TIMEOUT/MISSING）→ 有效状态与代表记录都取该 case
   **最后一次**有效测量。

汇总（作用于全部有效状态）：

- 待裁集合 = 性能期望集 − 豁免集；分母 = 待裁集合的大小。
- 性能期望集非空而待裁集合为空 → 性能 `证据不足`（豁免不能空转出通过）。
- 待裁集合内：任一有效状态为证据缺口 → `证据不足`；否则任一 FAIL → `不通过`；
  否则全 PASS → `通过`。退出码与状态词沿用 P「结果与退出码」。
- 「无性能要求」与 NO_REF 的既有分叉按 R「A5 结论」执行：CSV 无 `TC_PF_` 行才是
  `通过（无性能要求）`；有 `TC_PF_` 行而全配不到基线是 `NO_REF`，总体 `证据不足`。
  P「验收消费规则」中「comparable_pf 为 0 时性能记通过」一句与此冲突，并入时以
  R 口径更正。

判定示例（「测」= 有效测量轮结果）：

| # | 事件序列 | 有效状态（代表轮） |
| --- | --- | --- |
| 1 | 首轮 FAIL | FAIL（首轮） |
| 2 | 首轮 FAIL → 测 PASS | PASS（该测量轮） |
| 3 | 首轮 FAIL(0.72) → 测 FAIL(0.75) | FAIL（后轮，ratio 大） |
| 4 | 首轮 FAIL → 测 CRASH | FAIL（首轮；规则 3 先于规则 4） |
| 5 | 首轮 NO_KERNEL → 测 FAIL | FAIL（测量轮） |
| 6 | 首轮 NO_KERNEL → 测 TIMEOUT | TIMEOUT（末次测量） |
| 7 | 首轮 PASS → 豁免 | WAIVED（PASS 证据保留展示） |
| 8 | 首轮 FAIL → 豁免 → 测 FAIL | FAIL（豁免被撤销） |
| 9 | 首轮 PASS → 豁免 → 测 FAIL | PASS（撤销豁免后最早 PASS 恢复） |
| 10 | 首轮 FAIL → 豁免，此后无测量 | WAIVED |
| 11 | 首轮 FAIL → 测 PASS → 测 FAIL | PASS（最早 PASS 轮） |
| 12 | 首轮 FAIL → 豁免 → 中断轮 | WAIVED（中断轮不撤销豁免） |
| 13 | 首轮 FAIL → 无效轮里测出 PASS | FAIL（无效轮被跳过并告警，不进历史） |

已知代价（协议明示，报告透明化）：pass-once 使验收命题为「至少一次测得达标」，
临界例多试可能靠波动通过；报告必须展示每例尝试史（§8）。

## 7. warmup

`--warmup N` 是性能量具参数，任何一轮（含首轮）都可显式传入；受 G2 门控的只是
**默认值**（当前默认 0）。

- 语义：N ≥1 时，每个 case 的采样序列开始前，起**一个**裸 gtest 进程
  `<bin> --gtest_filter=<完整名> --gtest_repeat=N`（不带 msprof），跑完再进入采样；
  `--repeats > 1` 时也只在首个采样前预热一次。N=0 不起预热进程，即现行口径。
  合法范围 0–100，越界属参数错误。
- 计分无关：预热不产生样本，不改变 `calls_per_case` 的除数。
- 证据：`warmup_exit` 记预热进程退出码（整数）；拿不到退出码时为 null——N=0（未预热）、
  预热超时、启动异常三种情况都是 null，靠 `warmup` 字段的 N 值与逐例 `warnings` 里的
  原因文本区分。预热失败的去向只有两条，不留实现者选择：
  - **非零退出与启动异常**：记 warning，照常采样计分——裁决单源于采集轮证据链，
    预热进程起不来不构成对被测对象的判断。
  - **预热超时**（按 `--timeout`）：该例记 TIMEOUT 单例终态（属 §3 第 1 类，
    轮照常完成），避免一例吃双倍超时。

## 8. 报告与恢复

报告（A5 重跑后的当前投影）在性能节逐例展示：首轮状态与数值、各轮摘要
（轮号/kind/device_resolved/warmup/状态/ratio）、有效状态与代表轮（WAIVED 例另列
参考轮，见 §6 规则 1），以及逐例计数**有效复测测量次数**（有效测量轮中含该例的
次数，不含首轮；预热超时等证据缺口轮也计入——它是「测过几次」不是「测出数值
几次」）。汇总处列：**有效复测轮数**（全局数：有效轮总数，含豁免轮，不含首轮、
中断轮与无效轮）、中断轮号清单、无效轮号及原因清单（措辞含「该轮未生效」，避免
被读成已生效的复测）、豁免清单与理由、`PASS(复测)` 计数（定义：首轮非 PASS 而
当前有效状态为 PASS 的 case 数）。豁免与复测条目不受「超 30 条截断」限制，
必须完整展示。

verdict.json 记录：本次折叠消费的全部输入文件清单（首轮与各轮 JSON 路径 + SHA-256，
记录性质，供重演核对）、中断轮号、无效轮号及原因、折叠规则版本
`fold_protocol_version`（整数，本版 1，独立于记录 schema_version）。可重演承诺收窄为
**性能折叠可重演**，其输入边界是：首轮与各轮 JSON、运行时包 CSV 与规范化基线
（性能期望集按 R「A5 结论」由这两件重算，不从首轮固化恢复）、折叠规则版本——
同一组这些输入重跑折叠，得到相同的逐例有效状态、性能计数与性能结论。完整 A5
verdict 的重演还依赖 R「A5 结论」列明的其余输入（精度 JSON、check.json、manifest）。

A2′ 人工备注落 `<工作目录>/verdict_notes.md`（自由格式），A5 每次重渲染时原样并入
`report/report.md` 的备注说明；文件缺失按空处理。

启动与恢复（对话式、零上下文）。两种入口的最小输入：

- 测量复测：工作目录 + 点名 case + 可选 `--warmup`。
- 豁免：工作目录 + 豁免 case + 逐例理由（§4.3 必填）。

其余从盘上恢复——`<工作目录>/check.json`、`runtime/manifest.json`、
`runtime/results/` 文件名（run-id 与已占用轮号清单）、
`<产物目录>/intermediate/verdict.json`（产物目录见 R「A5 结论」）。run-id 多候选时
列出问用户；产物目录在工作目录外且找不到时要求用户显式给出。中断轮涉及哪些 case
从其阶段目录与日志读取；不可得时不阻塞，由用户重新点名。每个复测轮跑完必须重跑
A5，否则不构成最终报告。

## 9. 兼容性

- 无任何复测产物痕迹（无轮次结果文件、无阶段目录）的工作目录：A5 裁决的 verdict
  字段、逐例状态、计数、退出码与现行完全一致，报告与 verdict.json 不出现复测段落。
- 只有中断轮或无效轮、无有效轮的工作目录：裁决字段、状态、计数、退出码同样与现行
  一致（这些轮不参与折叠），但报告与 verdict.json 的诊断区照 §8 列出中断/无效轮——
  失败的尝试不允许从最终报告消失。
- 复测支持的机械判据：首轮性能 JSON 含 §4.4 两个扩展字段。缺失（旧版量具产物）即
  拒绝复测并提示该工作目录不支持；不做迁移。

## 11. 附录 A：换卡复测（未启用，待 G1 补证）

启用后对测量轮的变更：

- `device_requested`/`device_resolved` 允许不等于首轮值；换卡轮的 `device_requested`
  是显式物理卡号，`device_resolved` 记实际执行卡（重映射下两者相等）。
- 新增 `device_compiled`（编译期 `TEST_DEVICE_ID` 的进程内逻辑卡号）。**推导按
  harness profile 的绑卡约定**（profile 是 A1 探测写进 runtime manifest 的键名，
  见 R「A1 环境」），不按「显式即编译」想当然：
  - 编译期定卡域（`blas`）：首轮 `auto` → 0（auto 定卡协议按 `--device=0` 构建）；
    首轮显式卡号 N → N（该二进制在逻辑 N 上跑通了首轮）。
  - 运行时定卡域（`sparse_frame`）：恒 0——该 profile 的 `TEST_DEVICE_ID` 恒为 0，
    物理卡一律经运行时映射选择，首轮显式卡号只是映射目标，不是编译号。
  - 其他或未知 profile：推不出，该轮按环境失败路径停止（成为中断轮），不猜测卡号。
- 重映射串即 `ASCEND_RT_VISIBLE_DEVICES` 的取值：逗号分隔的物理卡号列表，第 i 项
  映射为进程内逻辑卡 i。按「目标物理卡落在第 `device_compiled` 位」构造——
  `device_compiled=0` 时就是目标卡号本身；为 N 时前 N 位填占位真实卡号、
  第 N 位填目标卡。
- 轮次有效性增加 PROF 落点核对，**范围限定为该轮实际产生的每个 PROF 输出目录**：
  存在的 PROF 目录名 `device_<物理卡>` 都必须与 `device_resolved` 一致；
  某例因 TIMEOUT/MISSING/CRASH/NO_KERNEL 等合法单例终态未产生 PROF 目录时，
  不因缺目录改判该轮无效——单例终态语义不受设备核对影响。
- 报告逐轮展示实际执行卡。身份与绑定校验不因换卡放松。
