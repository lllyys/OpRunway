# blas 换 msprof op 实施计划（plan v2，2026-09-23）

契约见 `blas-msopprof-spec.md`（下称 S）。本文只管实施顺序、分路、验证点与回滚，
不重复契约内容。

v1 到 v2 按 Codex 八维评审重写四处：落地顺序改成「先 accept 后量具」（v1 的对称耦合
论证不成立）；Gate 0 不再把「重跑旧 A4」设成不可替代的开工条件；补齐三处遗漏的入口；
验证门去掉不可达与证据不足的条件。

## 0. 前置：Gate 0 基线

动第一行代码前先固定住「改之前是什么样」，否则后面无法证明只改了该改的地方。

1. 记下两个 skill 全部 `SKILL.md` 与 `references/*.md` 的字节数，以及
   `skill_budget_lint.py` 的三条最紧链当前余量。**已完成**：accept 最大单阶段 32760 B，
   case-gen 32728 B。
2. 跑 `plugin/skill/repo-task-blas-accept/tests/` 全量，记下通过数。
   **已完成**：110 条通过加 12 条子测试。
3. **双后端对照样本。** 同一批用例各跑一次新旧后端，留下比值表。已在 ctpmv 上取得
   三个点（0.64x / 0.79x / 0.84x，见 S §6.1），实施时补 cherk 这个多 launch 算子。
4. 对两个 example 目录各跑一次逐字节一致性检查，确认当前是干净的。**已完成**：
   cherk 与 sasum 都退 0，六件齐全。命令是
   `package.py check --facts <example>/gen_csv.py`——FACTS 就是 `gen_csv.py` 本身，
   示例目录里没有单独的 facts.json。重渲用同一个 `--facts` 走 `render`。

第 3 条不要求「用旧后端重跑一次完整 A4」。身份与测量条件可核对的既有有效样本就够用；

## 1. 分路

六条路。**L2 与 L1 都动量具模板同一个文件，串行做。**

| 路 | 范围 | 依赖 |
| --- | --- | --- |
| L0 | accept 侧先撤 warmup 消费点（校验、展示、报告列） | Gate 0 |
| L1 | 量具后端：命令、产物解析、读数语义、失败判定、空间检查 | Gate 0 |
| L2 | 量具侧撤 warmup（参数、执行、序列化） | **L0 完成** |
| L3 | 撤落卡核对并补替代告警 | Gate 0，可与 L1 并行 |
| L4 | 文档：accept 权威化、case-gen 收缩、run-chain 删 A4″、复测协议改 | L0–L3 定稿 |
| L5 | 测试：新解析器单测、accept 测试重写 | 随各路行为改动落地 |
| L6 | 重渲两个 example | L1、L2 完成 |

v1 把 L0 与 L2 合成一路并称「必须同批」，那个论证不成立——兼容关系是单向的（S §7.1）。
**先删 accept 的消费，再删量具的生产**，第一步就是最终消费者行为，中间态两侧都能读，
不需要临时兼容分支，也允许分提交审查。

L3 与 L1 可并行，一个只动 accept 的设备段、一个只动量具模板，没有共享文件。

## 2. 各路改动清单

### L0 accept 撤 warmup 消费

删测量轮的 `warmup` 必填校验、逐例 `warmup_exit` 类型校验、复测史记录的 `warmup` 键、
复测明细表的 `warmup` 列、报告页脚相关措辞。

落地后旧量具产的记录照读，新量具产的记录也照读——这是中间态能安全停留的原因。

### L1 量具后端

改 `repo-task-blas-case-gen/assets/template/verify_performance.py`：

1. `_resolve_msprof` → 查找目标改 `msopprof`，四级顺序不变；补一次 `--help` 退 0 的
   可用性探测（S §4.1）。**`--msprof` 参数名保留不改**，只更新帮助文本与目标。
2. `_measure_case` 的 argv 构造重写成 S §4.1 的形态；删 `--application=` 拼装、
   `shlex` 依赖、`--ai-core=on` 与 `--task-time=on`；加 `--launch-count`（默认 512）。
3. 常量表：glob 改递归式 `OPPROF_*/**/OpBasicInfo*.csv`（两种布局都要覆盖，
   见 S §4.2）；`OP_SUMMARY_COLUMNS` 只留 `duration_us`；`KERNEL_TASK_TYPES` 整个删除。
4. `parse_op_summary` 重写并改名：递归收集全部命中文件的全部数据行，求和
   （S §4.3）。多份多行是多 launch 算子的正常形态，不是错误。
5. 计分前置条件四条：至少一份文件、至少一行、列存在、值为有限正数。
   外加**截断 fail-closed**：采到的行数等于 `--launch-count` 时判采集口径不支持，
   不计分（S §4.4）。这是唯一会把 FAIL 写成 PASS 的路径，必须有。
6. 失败判定按 S §5 的五步顺序重排，**环境错误排在 gtest 证据之前**。
7. 撤除法：`record["samples"].append(kernel_us)`，删 `/ args.calls_per_case` 与归一注释。
   `--calls-per-case` 参数保留但只接受 1（S §6）。**accept.py 的 A2 参数入口同步收紧**
   ——它现在接收任意整数，新产生的采集一律只接受 1；读取历史记录不加这个限制。
8. 逐例采样前的空间检查（S §5.1 第 2 条）：按**本次采集上限**算
   （`--launch-count × 2.2 MB × 峰值系数`），不按上一例的实际占用外推。
   日志写盘失败检查覆盖多种表述，不只 `Copy failed`；运行中的写盘失败仍归环境错误、
   整次采样不计分。
9. `PER_CASE_ESTIMATE_S` 改 6，注释写明「单 launch 用例实测 4.6–6.2s，多 launch 算子
   随 launch 数上升，仅用于开跑提示」。

## 3. 验证点

每个验证点过不了就停在那里，不往下走。

| 点 | 时机 | 判据 |
| --- | --- | --- |
| V0 | L0 完成 | accept 能读带 warmup 的旧记录，也能读不带的新记录 |
| V1 | L1 完成 | 采集完整、求和正确、截断检查会触发（三个必测项见下） |
| V2 | L2 完成 | 量具的执行、序列化与参数里不再有 warmup（不查文档与示例） |
| V3 | L3 完成 | 有用例断言核对已撤且替代告警已出 |
| V4 | L4 完成 | `skill_budget_lint` 与 `doc_style_lint` 双退 0；三条链余量均为正 |
| V5 | L5 完成 | 两个 skill 测试全量通过，新解析器覆盖 S §11 列出的全部形态 |
| V6 | L6 完成 | 两个 example 的 `package.py check` 退 0；文档与示例里 warmup 清干净 |
| V7 | 全部完成 | 四条跨契约路径实跑（见下） |

V1 的**正确性门**是「采集完整、求和正确、截断检查会触发」，不是比值落在某个区间。

已实测的 0.64x–0.84x 只有三个点，重复测量误差与算子差异都没有刻画，**不能当成所有
合法输入都要复现的硬门**——那会把正常结果误拦。它的用途是对照观察：比值明显跑出这个
范围时去查原因，查清了照样可以往下走。

V1 有三个必测项，缺一不可：

- **cherk**：仓内唯一已知的多 launch 示例算子，源码上每次调用 6 个 kernel，
  实测要对上。只有 ctpmv 与 sger 的单 launch 阴性结果不够。
- **截断路径**：人为把 `--launch-count` 调小于实际 launch 数，确认 fail-closed 触发。
- **sparse**：量具是共享的，至少跑一次 `sparse_frame` 剖面。

V2 只查本次改的两侧行为。全仓 `grep warmup` 在 L2 阶段必然有残留——L4 文档与 L6 示例
还没改，ATK 与历史文档也合法保留该词。清干净的判据挪到 V6。

V7 的四条路径，缺一不可：

1. 新首轮 → 新测量复测 → A5 折叠，确认复测轮进了折叠。
2. 旧历史两种情况分别验：**旧首轮加已有旧复测轮仍正常折叠**（绑定锚比的是复测轮与
   它自己的首轮，换 accept 不使其失效）；**新量具给旧首轮追加复测被拒绝**。
3. 环境失败中断轮（人为制造磁盘不足），确认判成环境错误而不是 NO_KERNEL 或 CRASH。
4. 换卡轮，确认替代告警出现在报告里。

**sparse 进回归范围。** 量具是共享的（S §1.1），至少跑一次 `sparse_frame` 剖面的
端到端，确认没被换后端打断。

## 4. 回滚

兼容关系是单向的，所以回滚也要按依赖顺序，不能按「组」对称地退。

| 已落地 | 能否直接回滚 | 约束 |
| --- | --- | --- |
| L0（accept 撤消费） | 否 | 盘上已有不带 warmup 的新记录时，恢复旧 accept 会让这些轮变无效 |
| L1（后端） | 是 | 与 warmup 无 schema 耦合，可单独退 |
| L2（量具撤生产） | 是 | 退回旧量具即可，新 accept 照样能读旧记录 |
| L3（落卡核对） | 部分 | 恢复旧 `PROF_*` 读取逻辑不会恢复对新 `OPPROF_*` 产物的核对能力 |
| L4（文档） | 是 | 删除为主，checkout 回来即可 |
| L6（重渲产物） | 是 | 必须跟对应模板版本同步重渲，不能单独退 |

一条通则：**可以先恢复旧生产者，不能在已有新记录时直接恢复旧消费者。**

## 5. 风险与止损

**最危险的是把落地顺序做反。** 量具先撤字段而 accept 的必填校验还在，每个测量复测轮
被判无效、静默跳过折叠，报告只剩首轮，而 accept 不报错退出。止损：L0 先行，V0 卡住。

**其次是 glob 只写扁平那条。** 多 launch 算子会扫空，表现为每例 NO_KERNEL，与「算子
没跑起来」无法区分。止损：V1 必须跑 cherk。

**第三是 L5 的假绿。** 常量改了而 fixture 没改时，glob 扫空走「缺目录不告警」的合法
分支，测试全绿但核对已被静默关掉。止损：V3 要求显式断言。

**第四是漏跑 L6。** 示例与模板的逐字节一致性在本仓内无人自动校验。止损：V6 明确列为
验证点，重渲单独成一个提交便于核对。

## 6. Codex 评审触发点

按 `.claude/rules/codex-review.md`，以下无条件触发：

两次都按八维出结论。
